## 1 结论与适用范围

本轮将生命模块逻辑结构展开为可执行的 SQLite 模式：Runtime 160 张业务表、一个 FTS5 虚拟索引及其4张影子表；Supervisor 6张控制表。字段字典逐表列出所有业务物理列、含义、类型、可空性、默认值与表级外键及唯一约束。

在已运行的正例、反例与合成数据流中，模式能保存跨模块关联，阻断已覆盖的非法引用和状态更新，保持版本、行动未知结果及承诺的恢复记录。结论是存储契约在当前测试范围内自洽，可以进入 Repository 和运行服务实现。

这不等于所有生命功能验证通过，也不等于所有业务约束已由数据库独立强制。没有调用真实 LLM、没有执行真实外部工具，没有进行断电、并发进程、文件系统损坏或完整删除服务测试。

## 2 从架构到 SQL 的明确补充

1. 增加 rule_definitions、capability_definitions、tool_definitions，避免规则、能力和工具成为无处落地的字符串引用。
2. 增加 cognition_concept_revisions，使概念的 current_revision_id 有明确目标。
3. 增加 goal_activation_batches，约束候选目标分布的定稿与冻结。
4. 人格、价值与身份锚点版本增加稳定根对象字段，使学习提交能连接同一对象的旧新版本。
5. 目标、意图、承诺增加 state_revision；转换记录增加 transition_no，由触发器核对并推进状态。
6. 时间区间、替代外键被拆为明确列与 CHECK，消除架构表中的斜杠式占位表达。
7. 所有 Runtime 数据按 instance_id 绑定；除有意跨实例的谱系父子边外，外键使用实例与目标 ID 的复合引用。
8. 新增受控删除例外：普通版本不可原地改写；cleaning 删除请求下可以脱敏内容并同步 FTS，但不能改版本所属对象和序号。

这些改变是原架构的字段和约束细化，没有改变第一阶段生命定义。

## 4 关键数据流的存储解释

### 4.1 输入到判断

perception_signals 保存原始材料，观察修订定位内容；cognition_episodes 关联活动与情境，通过 activity_context_refs 记录读到的观察／记忆版本；信念及预测引用相应证据和规则。可回溯来源不意味着来源必然可靠。

### 4.2 目标到外部行动

goal_items 与承诺关联；decision_records 草稿记录候选和因素，定稿时检查概率与选择；action_intents 绑定被选候选，action_attempts 和 action_results 分别记录尝试及结果。未知结果不会由数据库自动转为成功或自动重试。

### 4.3 反馈到长期修订

learning_feedback 引用实际结果；提案指向稳定对象；提交必须引用同一对象的两个不同版本。对应服务在同一事务中更新当前指针和学习记录。数据库验证对象归属，但更新收益、正确归因及审批仍由服务和评测决定。

### 4.4 健康到恢复

健康要求引用必要能力，检查方法和健康证据产生事件；维护计划关联授权与实际动作，维护核验记录方法、验证者和剩余损伤。数据库能保存独立性声明，无法仅凭一个枚举证明验证器真的独立。

## 5 约束落点与剩余服务职责

| 条件 | 当前 SQL | 服务层仍需负责 |
| --- | --- | --- |
| 关联存在、实例一致 | 延迟复合外键；提交时核验 | 每个连接开启 foreign_keys；处理提交失败 |
| 泛型引用类型 | registry 外键与不可变登记 | 审查 kind 与具体服务允许类型、业务对象是否已完整发布 |
| 版本归属 | 当前版本归属触发器、修订唯一键 | 当前指针非空、有效时间、所有依赖的失效传播 |
| 目标／承诺状态 | 状态机和序号强制 | 完成证据、用户解除权、逾期调度与通知 |
| 概率 | 单值范围、定稿分布校验 | 校准、候选完备性、采样算法和因素不重复计分 |
| JSON | json_valid | 每种结构的必填项、类型、schema_version 对应模型 |
| 时间 | 部分区间先后 CHECK | UTC 格式、未知原因、时间语义、时钟跳变 |
| 授权 | 引用授权记录 | 有效期、撤销、资源匹配、调用身份及实际操作隔离 |
| 外部副作用 | 幂等键唯一、分开保存尝试和结果 | 核验、超时、幂等工具调用、未知结果不盲目重试 |
| 删除 | 清理流程标记、修订例外和 FTS 同步 | 授权验证、派生图遍历、附件、日志、备份和物理擦除 |
| 健康 | 要求、证据、核验和损伤表 | 独立检测、实测阈值和功能性恢复判定 |
| 实例唯一活动 | 身份自引用与谱系无环 | Supervisor 单实例锁、停止权及迁移交接 |

不得把服务职责误写成数据库已经证明的功能。模式允许缺省或草稿态以解决循环创建依赖；服务必须在对象发布前完成语义校验。

## 6 性能与部署限制

Runtime 当前包含699个索引（含 SQLite 自动唯一索引）和407个触发器；准确数量以 validation-results.json 为准。大量外键与访问路径先以完整性优先，尚未做负载压测。后续应结合真实查询合并重复索引、评估写入开销，不把索引数量当作性能优势。

验证脚本使用宿主 Python 3.9.6，证明生成器与标准库数据库测试可运行；它没有替代实现架构中 Python 3.12+ 的应用部署验证。SQLite 目标环境必须具备相同所需能力。

全新建库脚本不是已部署库的增量迁移。WAL、备份窗口、迁移兼容、双进程交接、磁盘故障与中文检索效果还需集成验证。

## 7 复现

```sh
python3 scripts/build_database_schema.py
python3 scripts/validate_database.py
```

脚本仅在内存和临时目录构造测试数据库，并在 database/validation-results.json 保存结果，不初始化或修改真实生命实例数据库。测试结果与 SQL SHA-256 绑定，后续修改必须重新验证。
