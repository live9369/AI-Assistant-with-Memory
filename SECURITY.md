# Reporting security issues

This is an experimental, local-first project. Keep the management service on loopback. Source permissions, memory access and deployment verification are part of the system boundary.

Do not include credentials, personal conversations, database files or complete model inputs in public issues or pull requests.

After the public repository enables GitHub private vulnerability reporting, use **Security → Report a vulnerability** for sensitive reports. If that route is not available, open a minimal issue asking for a private reporting channel without publishing exploit details or private data. No email address or external reporting service is configured by this document.

Include the affected revision, platform, minimal synthetic reproduction and expected impact. Do not test against other people's instances or external model accounts.
