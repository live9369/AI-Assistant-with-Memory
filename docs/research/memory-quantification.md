## 摘要

本研究将数字生命的记忆操作性定义为：**系统对交互经历、事实知识、关系、承诺、技能线索和自身历史进行选择性编码、持久保存、情境检索、来源判断、更新、巩固与遗忘，并使这些信息在之后的认知和行为中产生可验证影响的功能体系。**

数据库只承担部分持久化功能。记忆是否有效，不能用记录数量、文件大小或“系统说自己记得”衡量，而必须沿完整生命周期量化：

```text
事件 → 编码 → 保存 → 检索 → 使用 → 结果反馈
         ↑       ↓       ↓       ↓
       选择    巩固    更新    遗忘／失效
```

V0.1 建议区分工作记忆、情景记忆、语义记忆、程序性记忆、自传式记忆和前瞻记忆。量化指标分为七组：编码质量、存储完整性、检索质量、来源与忠实度、更新与冲突、遗忘与删除、下游功能贡献。

记忆与认知保持双向关系。记忆为当前认知提供经历、知识和先验；认知决定哪些事件被编码、如何解释和是否更新旧记忆。人格可以影响注意和检索排序，但不能修改原始内容、来源和时间。自传式记忆支持身份连续性，但连贯的故事不等于真实历史；任何摘要、合并或修订都必须保留来源和版本。

## 当前边界补充：经历与经验判断

Q01后续设计裁决见[原始记录、学习产物与认知经验](../architecture/tool-observation-learning-q01-decision-v0.1.md)：文字／工具是来源差异；原始记录可先保存并作查证，学习提案、认知接纳状态及召回表示保持区分。该文补充研究依据和概念归属，不改变本研究的记忆分类，不表示新接口或实现已冻结。

记忆保存“发生过什么”及来源和情境，也可保存认知结果的记忆副本；“这些经历支持什么判断、方法在什么条件下有效”的当前经验版本由认知拥有。学习提出修正，认知保存；记忆副本不成为独立新证据或第二份权威版本。见[认知—经验归属](../architecture/cognitive-experience-ownership-v0.2.md)。本轮不改现有记忆类型和原始记录。

## 1 研究问题

本轮研究回答：

1. 数字生命需要区分哪些记忆类型；
2. 什么信息值得进入长期记忆；
3. 如何衡量记忆是否被正确保存和及时召回；
4. 如何区分事实、经历、推断、评价和关系信息；
5. 新旧记忆冲突时如何更新而不破坏来源；
6. 什么应当遗忘、降权、归档或删除；
7. 如何衡量记忆对认知、行为和身份连续性的真实贡献；
8. 如何避免错误记忆、循环确认、隐私越界和“删除后仍被使用”。

本文确定概念模型、变量和验证指标，不设计 SQLite 表结构、向量索引、提示词或具体检索算法。

## 2 理论参照与项目取舍

### 2.1 多记忆系统

认知研究通常区分情景记忆和语义记忆：前者与特定时间和情境中的经历相关，后者与脱离具体经历的知识相关。程序性记忆则表示如何完成某类任务的技能和规则。对数字生命而言，这些区分具有直接功能意义：一次交互经历、由多次经历概括出的知识和可复用操作方法不能被存成没有类型差异的同一文本片段。

项目同时引入自传式记忆，用于保存与自身身份、关系、承诺和长期变化有关的个人历史；引入前瞻记忆，用于保存未来需要执行或重新检查的意图。

### 2.2 ACT-R 的激活与检索启示

ACT-R 的陈述性记忆模型使用激活度连接练习、近期性、当前情境、检索概率和检索时间。其基本思想是：被多次使用、近期出现且与当前线索相关的记忆更容易被检索；随时间和不用而降低可访问性。

项目借鉴“基础激活 + 当前情境相关性 + 噪声 + 检索阈值”的思想，但不照搬人类记忆的固定衰减参数。数字存储不会像人脑一样自然丢失比特，因此需要主动区分“物理保存”和“认知可访问性”。

### 2.3 来源监控

来源监控研究强调，人们回忆信息时还需要判断其来源。数字生命尤其需要保留来源，因为同一句话可能来自用户陈述、外部文档、模型推断、系统规则或过去生成内容。内容相似不等于证据独立，系统自己的旧推断也不能在未来被当作外部事实重新引用。

### 2.4 长期对话记忆评测

LongMemEval 和 LoCoMo 等研究将长期交互记忆拆为信息提取、跨会话推理、时间推理、知识更新、拒答或信息不足识别等能力。这说明“能找到一条相似文本”并不等于记忆系统有效；系统还需要处理时间、更新、组合和正确弃权。

### 2.5 检索增强生成评测

RAG 评测通常区分检索相关性、召回、答案忠实度和答案相关性。对数字生命记忆而言也必须分开评估：没有召回是检索故障，召回错误内容是排序故障，召回正确但回答未使用是认知或生成故障，使用记忆后添加无依据内容则是忠实度故障。

## 3 记忆类型

### 3.1 工作记忆

工作记忆保存当前认知周期中活跃的事件、目标、候选假设、检索结果和约束。它容量有限、更新快速，通常不跨长期运行周期直接保留。

量化重点：

- 活跃项数量和复杂度；
- 与当前目标的相关性；
- 信息进入、更新和退出原因；
- 关键信息遗漏率；
- 过期信息残留率；
- 工作负荷对错误和延迟的影响。

工作记忆属于认知循环的一部分，但需要与长期记忆建立清楚的读写边界。

### 3.2 情景记忆

情景记忆保存特定时间、环境和参与者中的事件，例如一次对话、一个决策及其结果。它回答“发生过什么”。

最小内容：

- 事件内容；
- 时间和顺序；
- 参与者与对象；
- 情境和目标；
- 系统的观察、行为与结果；
- 原始来源；
- 当时的认知和置信度；
- 后续修订或评价。

量化重点包括事件完整度、时间顺序准确率、参与者归属准确率和结果可追溯率。

### 3.3 语义记忆

语义记忆保存事实、概念、规则及从多次经历中形成的一般知识，回答“什么是这样”或“通常怎样”。它可以来自外部可靠来源，也可以由多条情景记忆概括形成。

语义记忆必须记录：

- 命题及适用范围；
- 来源和支持证据；
- 置信度；
- 生效时间与可能过期时间；
- 反例和争议；
- 从哪些情景记忆概括而来；
- 更新历史。

语义化可以提高检索效率，但不能丢掉原始证据链。

### 3.4 程序性记忆

程序性记忆保存“如何做”的可复用知识，包括操作步骤、策略、工具使用条件、失败恢复和技能熟练度。它与描述事实不同：系统可能知道步骤，却未必能可靠执行。

量化重点：

- 适用条件识别准确率；
- 执行成功率；
- 执行时间和成本；
- 错误恢复率；
- 迁移到相似任务的能力；
- 版本和依赖变化后的失效率；
- 仅凭描述与实际执行之间的差距。

### 3.5 自传式记忆

自传式记忆由与系统自身历史相关的情景和语义记忆构成，包括身份变化、重要关系、承诺、长期目标、关键决策和学习转折。它支持跨时间连续性和“为什么现在是这个系统”的解释。

量化重点：

- 关键历史覆盖率；
- 时间与因果连贯性；
- 关系对象准确率；
- 承诺保持与变更可追溯率；
- 摘要是否能回溯到原始事件；
- 重启、迁移和版本更新后的恢复完整率。

自传式记忆不能通过生成一段连贯故事来验证。它必须由可追溯事件和版本记录支持。

### 3.6 前瞻记忆

前瞻记忆保存未来应执行或重新检查的意图，例如在条件满足时继续任务、在截止时间前提醒、等待结果后复核。

量化重点：

- 意图捕获率；
- 正确触发率；
- 漏触发和误触发率；
- 触发时间误差；
- 前置条件检查率；
- 完成后正确关闭率；
- 过期或取消后的残留执行率。

前瞻记忆不能绕过当前权限；过去合法的意图在执行时仍需重新检查环境和授权。

## 4 记忆单元的概念字段

每个长期记忆单元至少需要以下信息。这里定义的是概念要求，不是 SQLite 表设计。

| 字段 | 作用 |
| --- | --- |
| 内容 | 被记住的事件、命题、规则或意图 |
| 类型 | 情景、语义、程序、自传或前瞻记忆 |
| 主体与对象 | 信息关于谁或什么，避免关系混淆 |
| 时间 | 发生、记录、生效、更新和过期时间 |
| 来源 | 用户、环境、文档、工具、系统推断或规则 |
| 来源可靠性 | 来源质量、独立性和验证状态 |
| 置信度 | 当前对内容正确性的估计 |
| 状态 | 有效、暂定、冲突、过期、被替代、归档或删除 |
| 重要性 | 对目标、关系、身份、风险或学习的潜在价值 |
| 敏感性 | 隐私、访问范围和披露限制 |
| 关联 | 与事件、目标、人物、概念和其他版本的关系 |
| 版本链 | 原始记录、摘要、修订和替代关系 |
| 使用历史 | 何时、为何被检索和实际使用 |
| 删除规则 | 保存期限、用户删除要求和清理条件 |

内容与元数据同样重要。缺少来源、时间和状态的文本，即使语义正确，也可能在错误情境中形成错误记忆。

## 5 记忆生命周期量化

### 5.1 编码

编码决定哪些事件进入长期记忆、以什么形式保存。全部保存会造成噪声、隐私和检索负担；过度筛选则破坏连续性。

建议编码变量：

- 新颖性；
- 与当前和长期目标的相关性；
- 对身份或关系的重要性；
- 未来可复用性；
- 风险和承诺影响；
- 来源可靠性；
- 用户明确要求保存或不保存；
- 与现有记忆的重复和冲突；
- 敏感性与保存必要性。

建议指标：

- 应记事件捕获率；
- 不应记信息误存率；
- 关键字段完整率；
- 来源和时间标注率；
- 重复记录率；
- 敏感信息最小化率；
- 编码摘要相对原始事件的信息损失。

“重要性”不能完全由人格决定。人格可影响注意和主观意义，但用户指令、法律、隐私和项目规则优先。

### 5.2 保存与完整性

保存阶段关注记录是否持续、完整、可验证并受到正确权限保护。

建议指标：

- 写入成功率；
- 重启恢复率；
- 校验完整率；
- 损坏和丢失率；
- 未授权访问率；
- 备份与恢复成功率；
- 版本链完整率；
- 孤立记录比例，即无法关联来源或对象的记录。

SQLite 作为 V0.1 持久化选型适合保存结构化记录与版本关系，但具体索引、全文搜索或向量检索方式需通过实验选择。

### 5.3 检索

检索不是简单地“找到最相似文本”，而是依据当前目标、情境、时间、关系、来源和权限返回适当记忆。

可将候选记忆 `m` 的检索激活抽象为：

```text
Activation(m) =
    语义相关性
  + 当前目标相关性
  + 时间相关性
  + 使用频率与近期性
  + 重要性
  + 人物和关系匹配
  + 身份连续性相关性
  - 过期惩罚
  - 冲突与低可靠性惩罚
  - 隐私或权限屏蔽
```

该式不固定权重。权限屏蔽应先于排序；无权访问的记忆不能仅以低分参与检索。

建议检索指标：

- `Precision@k`：前 `k` 条中真正相关的比例；
- `Recall@k`：应召回记忆中被前 `k` 条覆盖的比例；
- `MRR`：首条正确记忆排名的倒数均值；
- `NDCG@k`：考虑不同相关等级的排序质量；
- 命中率与拒答率；
- 平均、p95 和 p99 检索延迟；
- 过期记忆误召回率；
- 错对象记忆召回率；
- 无权限记忆暴露率，目标应为零。

### 5.4 使用与忠实度

正确检索不等于正确使用。系统必须区分记忆原文、摘要、当前推断和最终回答。

建议指标：

- 记忆利用率：正确召回内容是否进入认知；
- 依据忠实度：结论是否得到召回记忆支持；
- 引用准确率：是否指向真正支持结论的记录；
- 范围保持率：是否把局部事实错误泛化；
- 置信度继承合理性：低可靠记忆是否被错误当成确定事实；
- 冲突披露率：相关记忆冲突时是否明确保留分歧；
- 下游幻觉率：使用记忆时是否加入无依据内容。

使用阶段应由结构化来源关系产生说明，而不是让模型事后自由生成一个听起来合理的记忆理由。

### 5.5 更新与冲突

新信息可能补充、修正、否定或替代旧记忆。系统不能直接覆盖旧内容而失去历史，也不能把所有版本同时当作当前事实。

建议区分：

- **补充**：新信息增加细节，不改变旧内容；
- **修正**：旧内容有误，新版本取代其有效状态；
- **时间变化**：旧内容曾经正确，但现在已变化；
- **来源冲突**：多个来源对同一命题不一致；
- **解释变化**：原始事件不变，但系统评价或理解发生变化；
- **撤销**：错误反馈或错误更新被取消。

建议指标：

- 知识更新准确率；
- 旧版本正确失效率；
- 冲突检出率；
- 错误覆盖率；
- 修订可追溯率；
- 下游传播修复率；
- 同源信息被误算为独立证据的比例；
- 当前版本选择准确率。

原始事件与系统解释应分开保存，使解释变化不会篡改事件历史。

### 5.6 巩固与概括

巩固将多条事件整理为更稳定、可复用的模式或语义知识。概括可以降低检索成本，但存在过度简化和强化偏见的风险。

建议触发条件：

- 多个独立事件重复支持同一模式；
- 模式在未来任务中有明确用途；
- 来源和适用范围足够清楚；
- 反例已被保留；
- 概括不会泄露不必要的敏感信息。

建议指标：

- 概括对原事件的覆盖率；
- 反例保留率；
- 适用范围准确率；
- 概括后检索效率提升；
- 概括后任务表现变化；
- 摘要与原始证据的一致率。

### 5.7 遗忘、降权、归档与删除

数字系统不会自然遗忘，因此必须区分四种操作：

| 操作 | 含义 | 原始记录是否保留 |
| --- | --- | --- |
| 降权 | 降低普通检索优先级 | 是 |
| 失效 | 标记内容不再是当前事实 | 是，并保留版本关系 |
| 归档 | 移出日常检索，但可在授权条件下审计 | 是 |
| 删除 | 按用户要求、隐私规则或保留期限移除 | 依删除策略，不得继续用于常规推理 |

建议遗忘或降权因素：

- 长期未使用且低价值；
- 已被可靠新版本替代；
- 与未来任务无关；
- 来源不可验证；
- 保存风险高于价值；
- 用户明确要求删除；
- 已超过保留期限。

建议指标：

- 过期信息抑制率；
- 有价值旧记忆保持率；
- 删除请求完成率和完成时间；
- 删除后再召回率，目标应为零；
- 归档误参与日常决策率；
- 因过度遗忘导致的任务性能下降；
- 因保留噪声造成的检索污染率。

“遗忘”不应只模拟人类衰减。对数字生命而言，它更重要的功能是控制相关性、冲突、隐私和认知负担。

## 6 记忆强度与可访问性

V0.1 不把记忆强度等同于内容真实性。建议把以下变量分开：

| 变量 | 含义 |
| --- | --- |
| 保存完整性 | 记录是否仍完好存在 |
| 可访问性 | 在给定线索下是否容易被召回 |
| 重要性 | 对目标、关系、身份或风险的价值 |
| 可信度 | 内容正确的估计程度 |
| 使用频率 | 历史上被调用的次数 |
| 近期性 | 距最近记录或使用的时间 |
| 情境相关性 | 与当前任务和线索的匹配程度 |
| 当前有效性 | 是否仍适用于当前时间和环境 |

一条记忆可以高频但错误、重要但低可信、完整保存但当前不可访问，或已失效但仍需保留历史。这些状态不能合并为单一“记忆分数”。

## 7 人格、认知和记忆的关系

### 7.1 人格对记忆的影响

人格可以影响：

- 哪类事件首先获得注意；
- 事件的主观重要性；
- 检索时哪些线索优先；
- 对风险、关系和新颖信息的敏感度。

人格不能影响：

- 原始事件内容；
- 来源和时间；
- 用户的删除要求；
- 已验证事实的版本状态；
- 权限边界。

### 7.2 认知对记忆的影响

认知负责决定编码、分类、关联、置信度、冲突和更新。为了避免循环确认，应明确标记“外部观察”“用户陈述”“系统推断”“系统评价”和“行为结果”。系统过去的推断不能仅因被存入数据库就在未来升级为外部事实。

### 7.3 记忆对认知的影响

检索结果进入工作状态，影响注意、假设、信念更新、预测和评价。认知记录应说明哪些结论依赖哪些记忆，使错误记忆能够被定位并撤销其下游影响。

## 8 记忆与自我连续性

自传式记忆支持身份连续性，但身份不等于所有历史文本的集合。V0.1 建议将以下内容视为连续性关键记忆：

- 身份和版本变化；
- 用户授权和边界；
- 长期承诺及其变更；
- 重要关系及对象区分；
- 关键决策和理由；
- 重大失败、修复与学习；
- 人格或目标发生长期变化的证据。

验证指标：

- 重启后关键记忆恢复率；
- 关系对象混淆率；
- 承诺遗忘率；
- 身份变更无来源率；
- 历史摘要证据覆盖率；
- 过去与当前自我模型冲突检出率。

项目仍不据此宣称系统具有现象性连续体验。这里测量的是功能和信息组织连续性。

## 9 端到端记忆验证

### 9.1 编码测试

提供应保存、不应保存、重复、敏感和相互冲突的事件，检查编码选择、字段完整性、隐私边界和去重能力。

### 9.2 检索测试

为每个查询标注应召回记忆，分别测试直接事实、跨会话组合、时间顺序、关系对象、更新事实和应当拒答的场景。报告 `Precision@k`、`Recall@k`、MRR、NDCG 和延迟。

### 9.3 使用测试

在召回结果固定的情况下测试认知与回答，区分“检索失败”和“使用失败”。检查结论忠实度、引用准确率、冲突披露和无依据扩展。

### 9.4 更新测试

先建立旧事实，再提供补充、修正、时间变化和错误反证，检查版本选择、历史保留、下游修复和来源独立性。

### 9.5 遗忘与删除测试

测试降权、失效、归档和删除的区别。删除后应使用多种语义改写和间接问题检查信息是否仍能被普通检索或回答恢复。

### 9.6 长期连续性测试

跨多会话、重启和版本迁移测试关系、承诺、目标及关键历史；同时加入相似姓名、时间冲突和错误自述，检查系统能否坚持来源证据。

### 9.7 功能贡献测试

比较以下条件：

1. 无长期记忆；
2. 完整历史直接输入；
3. 仅最近记录；
4. 当前记忆系统；
5. 移除某类记忆的消融系统。

比较任务正确率、行为质量、延迟、成本、关系连续性和错误率。只有当记忆系统相对基线产生稳定增益，才说明量化方案具有功能价值。

## 10 核心指标总表

| 阶段 | 核心指标 |
| --- | --- |
| 编码 | 应记捕获率、不应记误存率、字段完整率、重复率、隐私最小化率 |
| 保存 | 写入成功率、重启恢复率、完整性、权限违规率、版本链完整率 |
| 检索 | Precision@k、Recall@k、MRR、NDCG、延迟、错对象率、过期误召回率 |
| 使用 | 记忆利用率、依据忠实度、引用准确率、范围保持率、冲突披露率 |
| 更新 | 更新准确率、冲突检出率、修订可追溯率、当前版本选择准确率 |
| 巩固 | 证据覆盖率、反例保留率、摘要忠实度、效率与任务增益 |
| 遗忘 | 过期抑制率、有效旧记忆保持率、删除后再召回率、检索污染率 |
| 连续性 | 承诺保持率、关系对象准确率、身份历史覆盖率、迁移恢复率 |
| 功能 | 任务增益、行为预测增益、错误减少、成本和延迟变化 |

指标应按记忆类型、时间跨度、关系对象和任务难度分层报告，避免一个平均分掩盖关键失败。

## 11 常见故障分类

| 故障 | 含义 |
| --- | --- |
| 未编码 | 重要事件从未进入长期记忆 |
| 保存丢失 | 已编码但记录损坏或重启后消失 |
| 检索遗漏 | 记忆存在但相关查询未找到 |
| 错误召回 | 找到了相似但不适用、过期或属于他人的记忆 |
| 来源混淆 | 内容大致正确，但把系统推断、用户陈述或外部事实混为一体 |
| 使用失败 | 正确记忆已召回，但认知或回答没有正确使用 |
| 更新失败 | 新信息未替代旧状态，或错误覆盖真实历史 |
| 过度巩固 | 少数事件被概括为过强规则 |
| 遗忘不足 | 噪声、过期或不应保留的信息持续污染检索 |
| 过度遗忘 | 关键承诺、关系或技能被错误降权或删除 |
| 删除失效 | 已要求删除的信息仍可被检索或用于回答 |

不同故障必须由不同指标定位，不能都归结为“模型忘了”。

## 12 非目标与边界

V0.1 明确不作以下主张：

- 不把数据库容量等同于记忆能力；
- 不把长上下文窗口等同于长期记忆；
- 不把语义相似度等同于正确召回；
- 不把模型自述“我记得”作为记忆证据；
- 不把高访问频率等同于高真实性；
- 不把系统推断保存后升级为外部事实；
- 不要求复制人类记忆的遗忘曲线或生物机制；
- 不通过虚构经历填补自传式记忆空白；
- 不允许人格修改原始内容、来源、版本或删除状态；
- 不因身份连续性而无限保存敏感信息；
- 不将功能性记忆连续性解释为已经证实的主观连续体验；
- 不在本文件中确定具体数据库结构或检索技术。

## 13 V0.1 研究决策

1. 记忆是编码、保存、检索、使用、更新、巩固和遗忘的功能体系，不等于数据库。
2. 区分工作、情景、语义、程序、自传式和前瞻记忆。
3. 每条长期记忆必须保留类型、对象、时间、来源、置信度、状态、敏感性和版本关系。
4. 原始事件、系统推断和后续评价分开保存，防止循环确认。
5. 检索同时考虑语义、目标、时间、关系、重要性、有效性和权限。
6. 检索质量与生成使用质量分别评估。
7. 新旧冲突通过版本与状态处理，不直接覆盖历史。
8. 降权、失效、归档和删除是不同操作；删除后普通检索与回答不得恢复相关内容。
9. 自传式记忆支持功能性身份连续性，但不能作为意识或主观体验证明。
10. SQLite 保持为 V0.1 暂定持久化选型，具体检索方式由实验决定。
11. 记忆是否有效最终由其对任务、认知、行为和连续性的增量贡献判断。
12. 当前方案保持“初步研究 / 待实验验证”状态。

## 14 下一步

至此，项目主要组成均已有独立量化研究。下一阶段应建立统一的最小实验规范，其中记忆部分至少包括：

1. 一套带来源、时间、对象、更新和删除标注的测试事件；
2. 各类查询的标准答案与应召回记忆；
3. 编码、检索、使用和更新分阶段评测；
4. 跨会话、重启和版本迁移测试；
5. 删除与隐私专项测试；
6. 有记忆、无记忆和不同检索策略之间的对照实验；
7. 与人格、认知、动机和行为概率模型的联合实验。
