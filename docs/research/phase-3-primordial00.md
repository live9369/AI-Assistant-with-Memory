# 第三阶段：原初00唤醒

| 属性 | 内容 |
| --- | --- |
| 版本 | V0.1 |
| 状态 | 首个可运行最小原型 / 测试推理器模式 |
| 阶段目标 | 实现持久身份和经历支撑的离散活动，执行后核验并能在重启后接续 |
| 模型状态 | 未对接真实 LLM |

## 1 本次交付

实现 CLI、Runtime、外部 Supervisor、独立 SQLite 状态、请求记录、有限记忆读取、目标、承诺与单个 write_note 工具。Supervisor 每轮启动新的 Runtime 子进程，思考结束或等待批准后退出；数据库保存持续状态。用户启动 watch 时可进行有限时段的外部轮询唤醒。

活动链：输入持久化 → 观察记忆 → 目标 → 新构造的测试思考请求 → 参数校验 → 动作提案 → 本机用户明确批准 → 受控文件写入 → 文件内容核验 → 结果记忆、目标和承诺更新 → 子进程退出。

## 2 工程取舍

宿主提供 Python 3.9.6。首版采用标准库 sqlite3、subprocess、argparse 和 POSIX flock，不下载依赖，不搭建尚未必需的 HTTP 服务。正式部署 Python 3.12+ 的方案保留。

第一轮采用独立精简 schema，而不是完整160表。原因是先跑通实际活动、授权和恢复，再把已明确的运行行为归并到全量版本；这意味着上一阶段计划的“全量增量先合并”尚未完成，不得将其标记完成。完整设计、生成器和旧 SQL 未被替换，实例通过 application_id 隔离。

代码中的测试推理器只读取本次 JSON，确定性地产生受控笔记候选；没有网络调用和会话复用。历史内容以明确选取的最多8条记忆重新输入。这里的数量是首版工程限制，非生命科学常数。

## 3 运行和恢复规则

- 所有 CLI 运行操作使用实例锁串行执行，避免同一实例多个 Runtime 活动进程。
- 输入 source/key 去重，相同键不同内容拒绝。
- 测试思考最多3次尝试；一项活动最多接受一个结果，取消或 input_epoch 变化后不接受。
- 动作仅为 notes 下由活动 ID 确定的文件，批准绑定参数摘要；不支持任意路径或命令。
- 文件使用排他创建和 fsync；若文件存在则核对内容，不重复覆盖。回执丢失可依据原文件核验后续接，冲突进入 unknown。
- 承诺按到期时间转为任务，完成核验后才履行；休眠期间不生成经历。
- 用户 stop 状态保存在控制库，Runtime 重启和 Supervisor 再次运行不能自动清除。
- 外部 Supervisor 可修复缺失的受控笔记目录；文件或数据库损坏时不能擅自覆盖恢复。

这套恢复仅适用于当前可查询、幂等的单文件工具。一般外部工具需要后续设计中的 unknown、查询和授权恢复协议。

## 4 与五项判据的关系

| 判据 | 当前实际证据 | 限制 |
| --- | --- | --- |
| 边界 | 固定工具作用范围、批准参数摘要、实例数据库类型和进程锁 | 尚无通用权限／身份认证与操作系统隔离 |
| 持续性 | 身份、记忆、活动与承诺跨子进程保存 | 完整迁移、分叉与恢复世代未实现 |
| 自我维持 | 数据库检查、外部缺失目录修复与再次检查 | 不覆盖全部功能健康与代码回退 |
| 环境交互 | 实际写入本机文件并核验内容 | 只支持一个受控工具 |
| 适应性 | 历史结果保存并进入后续显式请求 | 尚未证明经验改变策略或提高表现，不判定通过 |

因此本原型不能被宣称已经满足全部生命判据。它是第三阶段的第一个可运行里程碑，不是第三阶段整体完成。

## 5 验证范围

首版运行测试10项，覆盖完整闭环、请求独立性、工具后回执前中断、思考中取消、输入去重与批准摘要、承诺跨冷进程履行、用户停止和健康修复、冲突结果不覆盖、单任务失败隔离，以及拒绝初始化其他数据库。与原有21项模式测试合计31项。具体最终运行结果以本轮执行记录为准。

已在 work/primordial00 初始化“原初00”实例并执行首次演示：输入“原初00的首次唤醒：保存今天的开始。”；测试推理器产生笔记动作，演示批准后写入文件并核验，活动 completed，留下观察和结果两条记忆。批准由本轮实现验收脚本发起，不冒称用户在独立界面进行了人工确认。

测试使用临时目录和测试推理器，不调用真实模型或外部网络。首版未证明真实模型有效性、通用副作用恰好一次、长期人格稳定性或主观体验。
