## 2 本地模型：已从适配代码推进到真实链路

采用独立 llama.cpp 服务加载官方 Qwen3-0.6B-Q8_0 GGUF，使用 CPU、两个线程、8192 上下文窗口和512输出上限作为小型接入验收配置。Ollama 适配器继续保留。选择小模型用于验证接入与执行闭环，不以它代表复杂任务质量上限。

程序来自官方 Ollama v0.40.15 分发包中的 llama-server；权重来自 Qwen 官方仓库。程序归档 SHA-256 为 `607c79d5d6315ef9d896db83adde736a4c0057196329843544e79b95afb260a8`；权重 SHA-256 为 `9465e63a22add5354d9bb4b99e90117043c7124007664907259bd16d043bb031`。本地 assets.json 记录全部56个程序／模型文件及内部库链接，启动前逐项校验并拒绝越界链接。

模型程序及权重在 work/isolated-model，未安装到系统目录。采用独立服务避免 Ollama serve 的默认主目录密钥创建行为。服务仅监听 loopback、以本地文件和 offline 模式运行，测试结束关闭，不注册开机任务。

实际验证了三条链路：

1. 真实模型生成符合 JSON Schema 的候选，记录真实输入／输出 token 和延迟；拒绝 history 等续接字段。
2. 真实模型 → 审批 → 独立工具子进程 → 文件核验 → 目标完成 → 结果记忆和指标。
3. 按版本目录启动的 Runtime → 真实模型 → 范围化授权 → 工具 → 活动完成和自动指标采集。

模型配置为追加版本，配置变更要求控制面停止，已有思考请求不被透明改写。每次独立构造 system 和当前 user 输入；所选记忆是本次输入，不使用服务端历史会话。可用性探针读取模型清单，不推理、不自动下载或启动模型。

证据：outputs/local-model-acceptance.json。模型接入依据 [llama.cpp 官方服务文档](https://github.com/ggml-org/llama.cpp/tree/master/tools/server)、[Qwen 官方模型页](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF)、[Ollama chat](https://docs.ollama.com/api/chat) 与 [模型清单](https://docs.ollama.com/api/tags)。

## 3 全部指标：采集工程闭环，不伪造科学结果

指标目录由第一阶段各报告中的具名指标和验证协议生成，覆盖 M01—M17，共188个条目：

| 类型 | 数量 | 采集方式 |
| --- | ---: | --- |
| 运行探针 | 25 | 从持久记录、文件及系统观测自动计算 |
| 依赖独立评测的指标／协议 | 163 | 带来源、案例、数据集和评测主体的观测进入后自动聚合 |

运行探针包括活动完成、队列及等待时长、记忆版本和来源完整性、关系证据、承诺履行、状态时效、资源、授权、工具成功／未知及耗时、身份、恢复锁、存储、制品、模型延迟与 token。

独立评测项包含人格效度、认知真值、检索相关性、语义忠实度、长期稳定性、反事实与学习回归等。外部评测器可以经服务接口或 API 提交，模型自报不能冒充独立评价。支持比例／评分均值、配对差、十区间 ECE、Precision@k、Recall@k、MRR 和二元 NDCG。实验仍须独立说明任务、量表和正负方向；统一采集器不是科学量表本身。

每项保存定义版本、来源、分子／分母、值、样本数、缺失原因、模型版本、数据集版本和来源制品。无真值、无相关样本、无实际调用时 value=NULL，不能填零或宣称通过。验证用合成评分只证明采集及聚合计算，不能用于宣称人格或认知实证成功。

Runtime 每个已处理任务后及空闲时每15秒自动采集。七维内部状态 R/W/U/C/T/D/F 分组保留：资源、工作负荷、已有预测熵、已记录冲突、分域信任、期限与组织完整性；没有预测或信任观测时保留缺失，不产生“心理真值”。每项有原始单位、证据和30秒有效期。

指标逐项字典：docs/research/phase-3-metric-dictionary.md。真实模型测试中的某些条目仍缺失，是有效的缺失记录，不是188项科学指标全通过。

## 4 版本、监视和兼容回退

候选源代码按内容摘要保存，拒绝链接和篡改；运行代码从版本目录加载。流程为：

```text
候选完整性／schema检查 → prepared就绪 → 激活门
→ 运行登记与running握手 → 稳定窗口 → 心跳和进程监视
→ 故障时停止候选 → 恢复旧活动版本 → 重启旧代码 → 记录结果
```

监视覆盖就绪前失败、激活后失败、运行中退出和心跳过期。前台 supervise 持有运行进程；明确用户停止或禁止唤醒标记优先，停止不触发回退重启，Ctrl-C 会持久记录停止状态。没有自动安装 OS 常驻服务。

真实临时进程测试验证了上述启动／退出路径。schema 2→3 使用受控的向前兼容扩展、校验和与迁移前快照，实际验证迁移后新版本失败仍可回到兼容旧代码，schema 与生命历史保持为3。禁止用数据库倒退来撤销已发生的外部作用。没有声称支持任意不兼容 schema 的自动回退；不在声明兼容范围内即拒绝启动。

当前注册工具仍为写笔记、读文件和列目录，受工作区限制。它是可扩展执行工程的当前工具集合，不冒充任意系统工具或操作系统安全沙箱。未知外部系统的“恰好一次”不能由有限测试普遍证明，当前实现以一次授权、幂等和显式未知状态处理风险。

## 7 交付状态与后续边界

本轮剩余工程进入限定范围内的隔离验收通过状态；正式实例保持原样，没有唤醒。下一步如进入正式部署／唤醒，应另行决定实际模型规模、工具范围和运行策略，不能由本报告自动触发。

仍待实证的是人格与认知构念效度、高维行为概率模型的拟合／校准、长期稳定性及开放世界表现。它们已有采集和评测接口，但本报告不把小型模型的短测试提升为这些科学问题的答案。

生命操作性定义、五项必要判据、身份不等于性格参数以及不冒称意识得到证实的边界不变。
