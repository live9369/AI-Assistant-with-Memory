# 信息更正的来源与时间上下文 TODO V0.1

日期：2026-11-14  
范围：当前正式版本，沿用V3候选及原证据校验，不创建隔离部署，不启用账户绑定、人格成长或额外记忆索引。

## 已核对

青禾杯已有两条held候选，内容相同、入库时间不同。现有snapshot缺少明确原始来源类型与原始时间，可能使重复整理旧话被误解为新证据。未知主体按活动保留，不能为了更正直接合并同名实体。

## 设计

新增原生请求字段 cognition_provenance，单独提供候选入库时间、来源引用、原始感知时间或记忆类型与直接来源时间。候选入库时间不等于事件发生时间；模型回复不构成独立观察；来源时间未知就明确未知。相同来源按引用复用，不重复复制正文。现有 cognition_snapshot 的结构与严格学习路径保持不变。

解释规则：仅当用户明确指向同一对象并表达更新/更正时，将新说法转述为最新报告，同时保留旧说法及来源。无明确更正或对象/时间不清时保留分歧并澄清，不凭新旧时间自动判断真伪。held候选不自动确认，未选择的私有内容不额外暴露。

来源读取继续使用现有可读性、当前修订及证据检查。元信息仅用于解释时间顺序，不成为新声明或操作授权的来源，也不新增自动事实采用接口。

## 正式验收前调度阻塞

首条更正消息尚未产生思考请求或模型调用，调度竞争记录明确因四项历史健康状态过期而不领取。此前完成时效规则只接入发送点，调度和准备仍使用旧历史判断。

本轮仅补齐原生调度、准备、发送三个入口共用即时健康评估与分阶段审计，沿用用户已批准的完整检查、完成后1秒消费及数据库一致性验证。保留全量状态采集及输入，未改预算、期限、权限或严格学习路径。原验收活动不改期限或账户，能在原期限内继续则继续，否则按真实状态留痕。

当前健康评估在原生上下文中还需保留既有状态ref/source_ref。即时测量通过后，使用标准States.observe发布四项真实新观测，以实测审计事件作为共同证据；沿用已有定义的TTL，不改写或续期旧观测。返回上下文保留完整状态字段和来源引用，而非用无来源的fresh标志替代。

调度旧实现还将历史采集和即时检查包在同一写事务内，导致正式取消请求返回database locked。本项只将原生调度读/测量阶段移出写事务；健康审计与新观测各自短事务，队列领取继续使用原Queue.claim的原子条件查询及租约。取消或被其他消费者领取的任务不会被复活，准备/发送依然重新复核全部健康、来源、权限和预算。严格路径原事务结构保留。新增两项直接验证长检查不持有写事务和领取前取消不复活。
