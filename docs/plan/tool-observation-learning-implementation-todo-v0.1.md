## 推进规则

- 每项按“核对冻结依据→补充本项实现说明→在隔离环境实现→保留正反例/故障证据→复核→更新状态”推进；依赖项未完成不得把后项标验收完成。
- 普通实现、隔离验证及 DEV/MECH 材料准备已经获授权；真实模型消费、正式评测、物理清理及当前实例操作仍分别过授权门。
- 状态使用pending/designing/implementing/validating/complete/blocked；具体进度以配套 JSON 为准。complete必须有对应交付物、代码版本、隔离结果、证据摘要和明确范围；计划、代码存在或静态检查不等于功能通过。
- 失败/未知/取消/缺证据必须保留；缺当前必要条件则blocked并写清条件，不靠新ID/新预算/反复重跑挑成功。改变冻结语义先走修订和兼容评审，不能边实现边暗改门槛。
- 实验根目录必须新建，使用合成数据和独立身份，禁止默认连接当前实例。每项退出检查子进程/临时服务已收尾；需要保留的实验数据加停止/恢复锁。真实破坏性清理仅针对明确授权的合成范围。
- 先用新建空库/合成2、3版本副本验证结构；当前实例迁移严格排到IM24。IM15桥接版本验证先于IM16隔离迁移，避免“先升级后发现不能安全回退”。

## 顺序与并行

用户最新调度要求：仅在**不同 IM 任务互不依赖，且各自全部依赖与启动条件已满足**时，分配不同子 agent 并行。每个 IM 由一个实现 agent 完整负责；不以同一 IM 的模块拆分代替任务间并行，不提前设计或实现尚未满足依赖的后项，不放宽验证与完成门。
