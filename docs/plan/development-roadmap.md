# 数字生命后续开发任务

这是后续实现的统一任务顺序。每项先设计、后实现、再隔离验收，更新状态与证据后才能进入下一项。当前运行实例不随源码更新自动部署，部署与唤醒只由用户授权的CLI执行。身份、记忆和历史不重建。

| 编号 | 任务 | 完成门槛 |
| --- | --- | --- |
| T01 | 冻结基线与回归题集 | 记录源码、实际部署、身份与能力范围；固定题集；可检查前后变化 |
| T02 | 活动执行和目标核验闭环 | 有限多轮独立思考；动作成功不等于目标达成；等待、继续、重启恢复、失败和停止可追踪 |
| T03 | 有来源的结构化认知 | 记录陈述、假设、疑问、预测和计划；保留证据及版本；反证与更正不抹掉历史 |
| T04 | 受控学习反馈闭环 | 反馈生成提案，隔离对照评估，审批采用或拒绝，支持CAS和回退，证明局部改善且不过度外推 |
| T05 | 目标 动机与内部状态 | 目标竞争、成本与投入、停止规则和状态联动可解释 |
| T06 | 高维行为概率 | 多特征候选评分、概率与采样进入真实主流程，效果可测 |
| T07 | 人格成长 | 来源和不确定性明确，稳定与慢变可测，单轮不剧烈改写 |
| T08 | 习惯形成与消退 | 情境特异、可抑制，反馈影响强度，不绕权限 |
| T09 | 人物与关系认知 | 实体和别名不误合并，条件信任及关系修复有证据 |
| T10 | 记忆巩固与质量 | 矛盾、更正、遗忘、删除和大规模召回可测 |
| T11 | 承诺与自主探索 | 有限自主问题、长期履约、兴趣、收益与休眠可验证 |
| T12 | 健康维护与自更新 | 诊断、修复、独立核验；源码更新失败可回退；用户停止优先 |
| T13 | 五项生命判据长期验收 | 边界、持续性、自我维持、环境交互、适应性分别通过 |

## 任务状态与进入规则

机器可检查的状态保存在 `task-status.json`。状态为 pending、designing、implementing、validating、complete。每项完成必须有设计路径、隔离结果路径、验收范围和依赖；complete不等于已部署。后续任务不得跳过前置项，确需调整顺序应先修改设计和本文件。

T01到T04采用有限工程范围：T02的目标核验只支持已登记的工作区文件验证器；T03的LLM解释作为带来源候选，不自动成为事实；T04先实现记忆修订的受控学习，不修改人格、价值或源码。通用复杂任务、自动事实真伪判定、全模块自主学习仍属于后续扩展，不因局部通过而宣称完成。
