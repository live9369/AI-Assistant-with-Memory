## 按什么流程解决

`Q01—Q02 对象与归属 → Q03—Q05 学习过程与产物 → Q06—Q07 接收和保存 → Q08—Q09 召回及有效性 → Q10—Q11 验收 → Q12 汇总冻结`

每项按同一流程推进：**提出问题 → 核对现有设计／代码／证据 → 比较方案 → 记录裁决及理由 → 写清接口影响 → 写出可判定的验收条件 → 检查上下游一致 → 标记设计解决。**

用户补充的通用工作方法：全部后续任务遇到不明确的实质问题，可以先查相关跨学科权威研究，不局限于计算机科学；包括认知／教育／生物／哲学／生命科学等适用领域。按问题相关性选研究，区分实验、理论、综合评议和哲学论证，写明原结论、适用范围、工程推论与裁决；不要求每题凑齐学科，不把脑机制直接等同软件模块。

状态使用：待处理、分析中、待裁决、设计已解决、冻结。设计已解决不代表代码已实现，冻结也不授权编码。后项可以记录发现，但不能在前项未裁决时把依赖字段定成正式接口。

## Q01开始时要核对的具体问题

以下保留原问题以追溯。[Q01裁决](../architecture/tool-observation-learning-q01-decision-v0.1.md)已回答概念及高层保存归属，[Q02裁决](../architecture/tool-observation-learning-q02-decision-v0.1.md)已回答操作权限／责任矩阵，两项分别核对，不把一项完成替代另一项。

1. “读到库存10”首先是本次观察，还是已经构成可用知识？需要哪些条件才能接纳？
2. “这次读取成功”与“这种方法值得继续使用”，分别由谁判断？
3. 学到的一条具体内容，是否需要独立于方法效果统计的经验类型？如何对应既有认知信念？
4. 记忆保存经验本体、可检索的派生表示，还是二者的不同部分？哪些对象只能引用，不能产生第二份权威？
5. 哪些原始经历仍可直接召回作证据，哪些只能在明确标注为未经学习处理时提供？

先用同一个“旧库存7→工具读到10→随后询问最新库存”的例子贯穿裁决，再用错误回执和矛盾来源作反例。示例不等于正式评测题，也不能把示例答案预塞给未来测试模型。

## 后续必须补出的接口说明

当前只列接口责任位置，不发明已存在的方法名：

- 执行／观察→学习：交付哪个不可变回执及定位、学习请求如何授权与去重。
- 学习→认知：提案类型、证据、旧版本、资格／未知、拒绝原因。
- 认知→记忆：被接纳的内容／版本或可读引用、派生范围、重建与幂等键。
- 记忆→认知／模型输入：查询用途、读取主体、返回类型、版本与有效性、引用与缺失信息。
- 更正／撤回→全链：失效通知、处理顺序、已准备请求处理、审计与恢复。

每个接口最终都要写：所有者、输入、输出、前置条件、状态变化、版本、幂等、失败语义、权限、预算及验收用例。具体字段随前项裁决再确定，不提前宣称冻结。
