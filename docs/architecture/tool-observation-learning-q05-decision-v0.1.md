## 1 问题与方案比较

需要表达四种不同问题：学到了什么候选内容、依据是否有效、目标所有者是否接纳、效果是否测得。不能仅用一段解释、一个confidence或一个qualified字段代替。

| 方案 | 问题 | 裁决 |
| --- | --- | --- |
| 单段文本加总分 | 来源、适用范围、未知和接纳状态无法分别核对 | 不采用 |
| 所有内容都装进现有收益统计事件 | 混淆具体内容与方法效果，破坏旧报告语义 | 不采用 |
| 分类型产物＋共同身份／来源＋按类型要求的内容＋独立资格维度 | 较多字段，但可逐项核对、与Q01—Q04一致 | 采用 |

## 2 针对不明确问题的研究与规范核查

| 来源／阅读范围 | 可用结论 | 工程借鉴与限制 |
| --- | --- | --- |
| JCGM 200:2012，VIM，第2.26条及相关说明。[BIPM正式文本](https://www.bipm.org/documents/20126/2071204/JCGM_200_2012.pdf) | 测量不确定度针对被测量所赋量值及所用信息，不等于测量误差或一般真假判断 | 保留量、单位、方法与测量不确定度；缺失时不填0。不把普通文件读数或模型主张自动当成经计量校准的测量结果 |
| HL7 FHIR R4，DataAbsentReason定义。[固定版本规范](https://www.hl7.org/fhir/R4/codesystem-data-absent-reason.html) | 区分不知道、未问、不适用、权限遮蔽及错误等缺失原因 | 医疗信息标准提供区分缺失原因的实例；采用项目自己的缺失词汇，不声称符合FHIR或提供临床解释，也不声称R4为最新版本 |
| W3C Web Annotation，定位相关部分。[正式规范](https://www.w3.org/TR/annotation-model/) | 原资源、引用和文本／字节位置不同；文本位置依Unicode码点，区间起点含、终点不含 | 定位必须关联指定内容版本与读取视图；不要求使用JSON-LD，也不把位置匹配当作语义证明 |
| RFC 6901，JSON Pointer，语法、求值及错误条件。[原文](https://www.rfc-editor.org/rfc/rfc6901) | 指定JSON文档中的值；对象成员名不唯一时定位不能确定，求值失败 | 结构定位明确解析文档和规则，不能对重复键默默取最后值，不能仅凭一个字符串声称定位成功 |
| Q01—Q04已查的来源监控、知识整合与PROV来源关系研究／规范 | 观察、解释和派生结果应可区分；来源关联本身不证明真假 | 延续原证据边界，不重复把格式或权威引用变成接受证明 |

检索日期：2026-11-08。以上包括计量科学、医学信息与技术规范，按具体问题采用；不是对人脑表征方式的证明，也不是通用知识资格的国际标准。另检索IPCC不确定性指南及AR6官方页面，但原页返回403，未将其列为已读依据或采用其概率／信心等级。

## 3 现状核对与兼容边界

当前学习评估已有gain、gain_status、qualified、source_refs及measurement_ref等字段；Cognition经验投影使用这些字段累计影子统计。现有qualified针对该统计样本的资格，不是世界事实已确认的通用标志。

本设计不得改写上述历史字段含义，也不把内容提案直接装入现有experience_saved事件。新语义类型、旧统计报告、M03接纳记录与M04召回表示要保持类型和版本边界；具体兼容读取／映射由Q12决定。当前API并没有本页定义的完整产物字典。

## 4 四类学习产物与下游记录

四类产物的业务生产者／写入者均为M14；其中可调用M03的解释能力，不改变最终接纳权。

| 设计类型名 | 含义 | 类型特有必需信息 | 不是 |
| --- | --- | --- | --- |
| ObservationExtract／观察提取结果 | 原回执可定位的观察与明确转换／解释候选 | 原观察引用、观察单元及定位、处理方法、内容范围、缺项／失败；没有可提取内容时明确结果 | 新的原始证据、已接纳的世界事实 |
| ComparisonAssessment／比较评估 | 观察与指定旧认识的关系及本次检查结论 | 提取结果引用、比较基线／覆盖、差异与可比性、理由、支持／反证／未解决项、处理结果 | 认知接纳决定或必有更新的证明 |
| UpdateProposal／修正提案 | 请求目标所有者接受某个有范围变更 | 比较评估引用、目标与预期基线、变更意图、逐项主张／范围／理由、证据及保留项 | 直接写入M03/M04的权限，或已发生的提交 |
| EffectAssessment／效果评估 | 对某次更新／方法的收益与旧能力保持给出测量或缺测说明 | 更新／方法版本、测量协议／报告引用或明确缺失、比较条件、指标／gain及状态、样本和成本信息 | 内容真实性判定、模型自评或预留预算充当实际用量 |

提取结果不是原证据的第二次产生。没有实质内容时可保存不足／失败评估，不要求形成空洞提案；没有效果评测时可记录未测，不能伪造完整报告。

下游由其他所有者产生：**M03的认知决定及版本、M04的召回表示及其状态**。M14只保存指向这些结果的关联，不能在自身产物里自填accepted或ready冒充对方已完成。Q06/Q07进一步定义两类下游记录，本轮不冻结其载荷。

## 5 共同字段字典

“必需”指语义信息必须具备；允许未知的值按第6节表示，不允许通过缺键自动推断。具体序列化及精确数据类型由Q12统一，不能把本表当已部署schema。

| 字段组／设计名 | 要求 | 内容与约束 |
| --- | --- | --- |
| contract_version、product_type | 必需，已知 | 草案／契约版本与明确产物类型；未知类型不可按旧文本兜底解释 |
| product_id、instance_id、producer | 必需，已知 | 产物身份、所属实例、生产模块／执行主体；不能借换ID产生新证据身份 |
| work_ref、purpose、processing_method | 必需，已知 | Q03工作及用途、加工方法／版本；模型参与时关联已有请求／模型版本，实际未知按Slot说明 |
| created_at | 必需，已知 | 产物的记录时间；不是事实有效时间，也不是原观察时间 |
| source_refs、derivation_links | 必需 | 明确来源／输入产物及其派生关系；类型允许无内容时说明原因，提案实质主张不能无依据 |
| body | 必需，按类型 | 第4节类型特有信息；不能用任意字符串回避结构与资格要求 |
| evidence_checks、readiness | 必需 | 第9节各维度检查与本阶段处理准备度，含检查者／时点／依据；不是下游接纳状态 |
| limitations、missing_items | 必需集合 | 范围局限及未知项的字段路径／原因；空集合表示经本次检查没有登记这些项，不表示全知 |
| access_dependencies | 必需 | 读取主体／用途及上游权限／有效性依赖；快照不是永久授权，不能泄漏无权者不可见的来源存在性 |
| revision_links、processing_identity | 必需，允许条件值 | 所替代／基于的产物及Q03处理身份语义；新产物没有前任可明确不适用，不能擅自设为某个旧对象 |
| downstream_refs | 条件必需 | 已有M03决定／版本或M04表示时给权威引用；尚未产生须说明未提交／等待，不由M14宣布对方成功 |

共同字段不要求把全部原文复制到每份提案。最小必要片段、可读引用和定位足够时避免多份正文；派生副本也须继续依赖原来源。旧产物在正常修订中不可覆盖，状态变化以所有者记录及关联表达；隐私清除依Q02/Q09另行处理。

### 类型内的关键字段

| 产物 | 内容字段与规则 |
| --- | --- |
| ObservationExtract | observations：每个单元有局部身份、claim_form、subject、predicate、reported_value、qualifiers、scope、evidence_refs及derivation；claim_form区分source_report、explicit_transformation、interpretation，不因格式成功升级内容资格 |
| ComparisonAssessment | baselines及comparison_coverage；comparisons逐项关联观察／旧版本、可比性依据、Q04差异、支持／反证／限制；outcome区分有提案依据、无变更、冲突、不足或按Q03阻断；它不是认知决定 |
| UpdateProposal | target.owner固定为实际目标所有者，本闭环认知内容为M03；target.mode区分existing/new；existing须有可核对target_ref和expected_revision，new不得假装已分配认知对象／修订号；operation与changes逐项描述新增、确认关联、时序补充、更正、限定、冲突标注等建议；rationale、preserved_content及unresolved_items保留理由和不改部分 |

## 6 未知值的统一语义：ValueSlot

对有可能未知／缺失／不适用的值使用概念包装：`status、value、reason_code、reason、basis_refs`。这是文档数据约定，不是实现类。status必需；value必需，以明确状态区分实际值与占位null；非known时reason_code必需，reason提供必要说明，basis_refs保留解释依据或明确空集合。

| status（设计词汇） | 语义 | value及限制 |
| --- | --- | --- |
| known | 此字段的记录值已知；不自动表示主张为真 | value保持实际类型，可为0、false、空字符串、空集合或原来源明确的null；须说明字段语义及依据 |
| unknown | 应有／可能有该信息，但当前无法确定 | value=null，说明未知原因，不猜值、不填0 |
| not_collected | 此次流程没有采集／执行该项 | value=null；例如未做效果测量，不能暗示评测失败 |
| not_applicable | 对当前对象／产物类型没有适用值 | value=null，须有适用性理由；例如新目标没有旧修订，不可用来掩盖缺失基线 |
| withheld | 因当前权限／隐私不能呈现 | value=null，不在reason／basis_refs中泄漏被遮蔽内容或存在性；公开视图按权限决定是否连此标记也不返回 |
| conflicted | 有不相容候选，尚无被选定值 | value=null；可读的候选分别保留身份、范围及依据，不能直接选平均数 |
| invalid | 曾提供的值／定位不符合完整性、类型或有效性要求 | value=null；原错误留授权审计，不能把非法值混入正常计算 |

关键区分：

- 结构必需键缺失是格式不合格，不自动等于unknown。可选字段未传只说明没包含，接收者不得推成false、空结果或不适用。
- `known + value=null`只能用于“原来源明确报告null”等有明确语义的内容，不代表现实属性已知为空；若测量值尚不知道，应为unknown，不是known/null。
- `known + value=[]`是某项已定义集合的已知空结果；不能代表没有未知、没有风险或全世界不存在对象。
- 未知、未采集、不适用不参加普通数值平均；数据中原始null与本协议占位null靠status及字段含义区分。
- 条件、时间或来源范围未知时保持未知，不能隐式解释为“任意条件、永久有效或所有来源”。

reason_code候选如no_prior_prediction、not_measured、missing_unit、ambiguous_entity、incomplete_source、source_reported_null等，最终代码表在Q12冻结；不能仅剩一段无法统计的自由文本，也不能因代码匹配就自动批准内容。

## 7 来源与定位字典

### 7.1 EvidenceRef的必需语义

| 字段组 | 要求 |
| --- | --- |
| source_instance、original_result_ref、receipt/artifact_ref、evidence_ref | 按来源类型明确原链；已有工具回执类型须能追到对应原结果。非工具来源不得伪造工具ID，以来源类型规则明确不适用 |
| source_revision、content_digest | 固定原工件／来源版本、摘要算法与摘要，不用“当前路径内容”代替；摘要相同不证明来源独立 |
| media_type、encoding、view_ref/view_digest | 明确定位针对原字节、解码文本还是已声明的解析视图；不同视图的摘要不能混用 |
| locator | 精确定位类型及参数，见下表；只给结果ID或哈希不足以支持复杂工件中的一项具体主张 |
| origin_method、observed_at、source_reported_time | 区分获取方法、观察时点、来源声称的事件／有效时间；缺项以Slot表达，不由产物created_at补齐 |
| coverage、derivation_refs、access_dependencies | 保留分页／截断／读取范围、加工链与权限依赖；引用副本不能切断原始来源 |

### 7.2 定位方式

| locator.kind | 设计要求 | 不能做什么 |
| --- | --- | --- |
| json_pointer | 针对指定、确定解析的JSON文档按RFC 6901定位，转义及数组位置遵循其规则；成员名重复导致不能确定的定位须失败 | 不能静默取最后一个重复键；指针存在也不证明解释正确 |
| text_range | 绑定指定文本视图；使用Unicode码点、零起点、起点含／终点不含的[start,end)，可用最小quote及前后文辅助核对 | 不能把字节偏移或UTF-16单元当码点；不能在变化原文中按相同数字继续定位 |
| byte_range | 绑定原字节和编码相关信息，使用零起点半开区间；解码／转换另记方法 | 不得与文本位置混算，也不能将任意切片当完整语义 |
| whole_artifact | 可用于工件整体状态或本身只有一个原子观察的完整正文；应说明适用范围 | 不能用大对象整体引用掩盖具体主张找不到出处 |

引用原文只复制权限允许的最小必要片段；不能为了方便定位把完整私密正文放进每份公开提案。重排、规范化、OCR或嵌套解析如改变定位空间，必须有派生视图及转换身份，保留原工件。定位失败按invalid／unknown及Q03处理，不改来源内容凑匹配。

例如原回执中`/evidence/text`是字符串，字符串内又编码JSON。若要指向内部value，必须关联先取该字符串、再按声明解析得到的视图及内部`/value`；不能声称原回执顶层直接有`/value`。仅解析出10而没有这条链，不足以通过来源核对。

## 8 适用范围Scope

每条实质主张必须有自己的scope；共享scope可以引用，但不能只给整批提案一个模糊“适用于全部”。

| 语义字段 | 表示要求 |
| --- | --- |
| subject/entity | 已确认对象引用或明确的候选标签／解析状态；标签相似不等于同一对象 |
| property/claim_target | 讨论哪个属性／命题，区分“来源报告值”与“现实对象值” |
| temporal_scope | 类型明确为观察报告时点、来源所述有效点／区间、一般规律候选等；具体时间及边界以Slot表达。未知终点不等于永久，未知起点不等于无限过去 |
| conditions/context | 声明成立所需的任务、环境、方法及条件；未检查条件不能省略后视为普遍成立 |
| location/domain | 空间、业务或问题域；不适用要说明，未知不扩大为全部区域 |
| unit/granularity | 单位、尺度、近似／粒度，保留原始字面信息；无单位不默认为无量纲 |
| coverage/population | 读了哪些范围、几页、是否截断、关于哪些样本／对象；有限列表不能成为全域否定或普遍规律 |
| exceptions/limitations | 已知反例、例外及未排除解释，关联相应证据；空列表不保证没有未知反例 |

变更建议的scope与原认识scope都要可定位；范围收缩应表达具体收缩之处，不只换一个值。确需时间／单位／别名转换时附规则与依据；转换能力未知则不可比较，不凭较新产物created_at认定世界变化。

## 9 资格维度与写入权

下面为语义词汇草案，不是完整运行状态机。维度独立，不合并为一个“合格”布尔值，不按一列自动推导其他列。

| 维度 | 设计状态示例 | 谁记录／怎样解释 |
| --- | --- | --- |
| 来源访问与有效性快照 | readable、temporarily_unavailable、revoked、deleted、unknown | 根据M12及源所有者的当前依据记录检查时点／引用；M14不能自授权限，使用前仍须重检 |
| 定位／完整性检查 | not_checked、matched、unresolved、mismatch | M14记录提取检查；matched只说明匹配来源，不证明内容真 |
| 对有限主张的支持检查 | not_assessed、supports_scoped_claim、insufficient、conflicting、not_applicable | M14的有依据评估，保留规则／审阅者与支持／反证；不是M03接纳结果 |
| 本阶段处理准备度readiness | not_checked、ready_for_handoff、needs_material、blocked、not_applicable | M14对本阶段的判断；ready_for_handoff只准交接，仍受停止／权限／版本等约束 |
| 认知接纳结果 | 未提交／待处理／候选持有／有范围接纳／拒绝／被替代／失效等 | **只由M03权威记录提供**，M14只关联其引用。精确状态与转移交Q06，不预填accepted |
| 召回表示结果 | 未请求／待生成／已生成／失败／过期／撤回等 | **只由M04权威记录提供**，并非认知真值。精确状态与恢复交Q07 |
| 效果测量 | not_measured、incomplete、measured、invalidated、not_applicable | M14基于合格报告或缺失原因记录；measured不自动使内容正确或被接纳 |

每项资格快照都要有检查者／方法、检查时点、所核对的来源与目标版本、原因／依据。状态变了不回写旧产物冒充当时已知；当前资格沿所有者记录及依赖重算／读取。Q09定义传播，Q07定义关联保存和原子性。

“可用”必须说明用途：可交接、可作原始证据查证、可呈现候选、可作为当前认识使用，含义不同。默认不得从产品存在、source readable或ready_for_handoff推到可作当前事实使用；最终认知使用规则交Q06/Q08。

### 不确定性也不能压成一列

- **内容／证据局限**：对象未消歧、时间未知、来源冲突、推理前提不足等，分别写入相应Slot及limitations。
- **测量不确定度**：适用时才关联测量量值、单位、方法和来源；没有估计时unknown／not_collected，不是0。普通文件报告值没有该项可标明不适用理由，但其真实性仍可能未知。
- **概率／模型信心**：若来源自报0.9，可保留为“模型自报值”及出处；无校准依据不得当可靠性概率或接纳门槛。项目不凭语言标签自动生成70%等数字。
- **学习效果未知**：只说明未测或测量不足，不能推导内容错误；同样，已知gain=0不等于没有内容变化。

## 10 gain、计数和成本的特殊规则

EffectAssessment只有在相应协议的有效测量完成时，才可将gain记为known的数值，并关联可重算报告、指标方向、适用case及候选／基线版本。

- 沿用现有测量协议时，positive、negative、measured_zero、unknown保持原语义；unknown的数值占位为null并给原因。其他量尺不得偷用相同字段含义或混算。
- gain已知为0必须来自真实零差值测量，不由未测／空集合／失败补0。负收益如实保留，不因未达预期删证据。
- 样本数、来源数、交付数、复习次数及独立样本数分开；每个数有定义和范围。已知0与未知数量不同，独立性不能凭不同ID或多份摘要推定。
- 实际token、调用、耗时与预算预留分开；缺供应商用量不估成0，单位和统计范围须明确。保留已知部分及未知项，不把已知合计冒称总成本。
- 样本不足或分布不明时，不生成缺乏方法依据的置信区间／可靠性概率。报告失效后当前视图不得继续将其当有效测量，旧历史保留，细则交Q09。

## 11 两组文档示例

示例是字段语义片段，**不是完整合法请求、可运行schema或模型输入**。S、R、V等是说明用占位引用，未来不得将其直接提交为真实证据。

| 情况 | 内容／范围表达 | 资格与未知表达 |
| --- | --- | --- |
| 文件S在观察时点t1的原正文明确报告10；没有效果评测 | reported_value：known/10；claim_form：source_report；scope指向S在t1的报告；EvidenceRef关联原回执及实际定位 | 定位matched，支持仅限来源报告；ready_for_handoff须检查其余条件；M03结果未提交；measurement_state=not_measured，gain为not_collected/null，原因not_measured |
| 两个可比来源分别报告7和10，没有胜出依据 | 两个观察单元各有known值及独立出处／相关性说明；共同待判命题的值为conflicted/null，保留候选引用 | support=conflicting；不能强填单一值或平均8.5；可形成冲突标注提案，不等于能提交“值=10”的内容更新 |

前例的时间是观察报告时点，不自动成为现实库存的有效期；若单位缺失则单位unknown，不自动填件。第二例是否两个来源独立也须另判，冲突并不证明独立。

ValueSlot最小片段可写为以下说明性数据，强调状态的区别，不表示接口已经定稿：

```json
{"status":"known","value":0,"reason_code":"observed_literal","reason":"原字段明确为零","basis_refs":["S"]}
```

```json
{"status":"not_collected","value":null,"reason_code":"not_measured","reason":"本次没有效果测量","basis_refs":[]}
```

原来源明确null时，known/null配source_reported_null表示“来源确实给了null”，不据此推出被测／现实属性不存在。未来完整例子、schema验证和不同语言序列化一致性由Q11/Q12补齐。
