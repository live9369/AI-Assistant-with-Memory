# IM01 实现说明：基线、追溯与隔离夹具

2026-11-09；依据TL-LOOP-0.1与实施TODO。用户已授权从实施TODO开始编码及隔离验证，可启用独立子agent；没有授权真实模型支出、正式评测、当前实例操作或24小时实验。

## 交付与范围

1. 冻结规范/来源摘要复核及19表、10操作、9状态轴到IM任务与验收题的追溯表。
2. 全新隔离根、合成schema2/schema3夹具：原始身份、记忆、权限、未来承诺、历史和保留失败证据策略。
3. 实施计划只读检查与状态门控：按真实用户授权记录、依赖与匹配验收证据决定可推进项，不启动任务、模型或实例，不改主路线T/Q状态。
4. 独立验收脚本记录本项测试、冻结摘要、相关源码在验证期间稳定和结果；完成后才能解锁IM02及并行准备的后续路径。

本项不是19表DDL实现、TL业务闭环或现有实例迁移。引用旧代码仅复用Store.prepare、真实迁移及服务入口，不能用合成PRAGMA冒充schema3。

## 并行文件责任

主agent维护计划门控、IM01证据与总设计；fixture子agent只写evaluation夹具/测试及其设计说明；trace子agent只写追溯文档/JSON；独立review子agent只读核对。冻结规范与共享计划只由主agent维护，子agent不得操作实例或业务配置。

## 门控规则

计划状态不改变宿主权限。JSON只记录用户已有授权，不是可通过编辑字段自行取得模型或正式实例许可的机制。没有通用自动执行器，计划检查与转移不会调用业务模块。

冻结记录及规范/决策摘要必须匹配；历史code_snapshot漂移单独报告，不把后续正常实现误判为不可推进。每项非pending状态必须前置complete；设计路径限项目docs；complete需证据路径、摘要、任务ID、passed=true、冻结设计绑定及验证期间源码稳定。证据是相应版本的历史验证，不因后续正常修改自动声称已验证新版本。

实现/隔离测试授权只覆盖普通implementation/evaluation_implementation，以及常规DEV/MECH材料准备；独立正式材料角色、真实DEV/正式模型及当前实例仍分别过明确门。blocked记录缺少条件，不把缺授权当工程失败或自动转complete。

## 验收条件

- 拒绝已存在根及符号链接/祖先，调用Store/Control前阻断；不读任何当前实例内容。
- schema2与真实迁移后的3具有可核对的合成身份、记忆、权限、未来承诺及历史，保持WAKE_DISABLED、user_stopped及无进程。
- 正常退出/异常/需要保留的失败均停止锁定；拒绝已有目标时不清理或修改其内容。
- 追溯覆盖19/10/9项，旧实现与新增任务不混称完成；字段引用与验收ID可查。
- 门控拒绝依赖跳过、证据缺失/假passed/错task/摘要变化/冻结绑定变化，正确证据可完成并仅解锁合法后项。
- 本项验证只运行针对性离线测试及静态追溯检查；真实模型/当前实例无调用。
