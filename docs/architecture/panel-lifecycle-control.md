# 面板配置应用与进程控制 V0.1

状态：已实现，已通过临时实例核心流程验证。用户已同意以面板为主要入口，CLI 保留为备用。

## 核心流程

root 在实例配置页修改一组设置，确认差异后选择“保存并应用”。后台先校验字段和版本，再记录持久停止、等待原进程退出、保存配置、启动原有部署、等待部署就绪。面板独立运行，不随实例停止。

启动、停止、重启和配置应用共用一个生命周期服务。操作异步执行，以持久记录展示阶段、结果、失败原因。每个实例同时只接受一项操作。CLI 提供相同服务入口。

普通重启使用上次部署，不暗中部署当前源码。首次启动没有部署时才准备当前源码。禁止唤醒锁、模型额度复核锁、恢复核对锁继续生效，面板不自动移除。停止等待有上限，不强杀正在执行的外部操作。

## 并发与失败

每次操作使用独占文件锁，由独立工作进程持有；启动后的部署监督进程不依赖 HTTP 服务。持久操作记录使用原子替换，前端轮询最新状态。操作中途的额外 CLI 停止优先，恢复前核对停止命令，不自动覆盖新的停止意图。

保存前采用配置版本比较，失效版本在停止前拒绝。启动失败时，已保存的一组配置通过原有服务追加回滚版本；不还原数据库快照，不回退记忆、账户、身份标识或历史。旧配置恢复成功后尝试启动原部署；无法恢复时保持停止并明确显示错误。进程异常退出的操作显示中断，不自动重复执行。

接口：GET /v1/instance/lifecycle；POST /v1/instance/lifecycle/{start|stop|restart}；POST /v1/instance/settings/{group}/apply。写请求必须明确确认。所有接口沿用账户 root 鉴权和受保护实例边界。
