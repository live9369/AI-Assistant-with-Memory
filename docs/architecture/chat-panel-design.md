# 聊天交互增量设计 V0.1

聊天页展示用户消息、已接受的公开回应、等待/审批/失败状态，支持继续发送和新建会话。思考内部过程不展示为聊天。每条消息对应独立活动和thought_request；各次LLM调用继续独立，显式对话上下文由系统构造，不使用供应商会话续接。

复用context_snapshots.attributes_json中的chat元数据及activities.predecessor_activity_id，无新增表或迁移。聊天输入、关联和队列在同一SQLite事务保存。客户端以固定thread_id、幂等消息键和expected_last_activity实现重试与并发控制；同一会话上一消息处理中或尚有待审批动作时禁止继续发送。新消息不是重写上一思考请求，也不会把等待中的旧活动恢复后复用原请求。

GET /v1/chats、GET /v1/chats/{id}、POST /v1/chats/{id}/messages沿用控制令牌与来源保护。请求只保存活动，不在HTTP中执行推理。引擎在prepare时把先前有限用户消息和已接受的公开回应作为conversation_context数据纳入新请求，固定输入artifact/hash，绝不把引用历史视为权限。保留最近8条上下文记录，并限定8000字节，显式返回省略数量；长期记忆仍走既有选择机制。新消息上限4000字节。

面板可自动刷新回应，发送草稿仅在页面内存保留，不存浏览器storage，不在刷新中丢失。空闲显示等待，失败显示错误；动作审批仍在活动与审批页面。聊天不提供部署/启动/唤醒。

先用独立全schema实例验证多轮输入、显式上下文、新请求身份、幂等、并发、旧/拒绝结果隔离及真实Codex独立会话。当前运行实例与其已部署源码快照不变。更新正式运行器只能由用户后续CLI停止/部署，不能靠面板热替换。本轮关闭历史面板监听，保留所有实例目录，不删除生命痕迹。

## 认知连续性与共享记忆增量

会话ID只界定直接对话上下文，不隔离同一实例的授权记忆。每次新任务显式重建最近对话和全实例召回，仍使用新请求。召回排除当前输入自身，使用大小写归一的英文名、中文双字重合、自传线索和近期经历排序，并保留每条选择理由；这是可解释启发式，不声称通用语义理解。所有记忆均属于实例经历，但不应把全部原文每次塞入模型。访问权限和删除状态仍有效。

公开回应以生成来源追加为记忆；旧版本的已接受公开回应在后续任务处理时幂等补录，不修改原始请求或结果。生成回应是经历，不等于内容已验证为事实。当前基础实现会扫描活动记忆并逐项检查，数据增长后需专门评估性能和检索质量。
