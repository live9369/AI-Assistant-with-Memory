# T11 承诺与自主探索实施报告

版本 V0.1；状态：有界工程验收通过；范围：有界工程实现与隔离验证，不部署当前实例。

## 实现结果

1. 承诺：显式登记受益方、内容、开始时间、截止时间及核验条件；通过既有状态机确认并激活。开始时间参与持久队列和休眠交接，恢复后唯一关联目标活动。用户已有工作优先，不为承诺绕过权限和资源门控。
2. 履约：复用 TaskLoop 的独立文件内容核验，工具成功不能直接记履约。记录核验工件和证据，逾期未完成记违约，释放取消未完成工作并保留历史；已有终态不能覆盖。
3. 探索：复用原 V2 的证据许可、只读工具、预算、访问次数、轮次、间隔和停止规则。新增声明兴趣与有限排序，收益重复会降低再次选择倾向，不增发预算。
4. 收益：仅消费真实 Executor read_file 回执，并检查内容哈希、路径和资源签名；首次核验同一事实与文件版本记1，重复记0，不能核验记null。肯定和否定观察均可计入事实覆盖。认知经验统计仍维持原来的影子模式。
5. 观察：CLI 增加状态、开关、登记、释放和问题偏好操作；面板思考详情在“探索”组显示该次独立输入中的承诺和兴趣快照。没有新增部署、启动或唤醒按钮。
6. 持久化：复用已有承诺、活动、目标、任务队列和不可变事件工件，不重建身份或记忆，不新增重复承诺表。任务开始、履约审计、取消与工具结果使用同一协调锁顺序，避免事务内反向获取控制锁。

## 验证范围

新增35项临时实例测试覆盖：默认兼容、控制权限、停止配置门控、时间与验证参数、幂等、未来开始、唯一活动、重启恢复、用户优先、独立核验成功、目标不匹配、未知效果、履约不可绕过、截止违约、释放、关闭后义务保留、重复队列、兴趣排序、收益1/0/null、跨题去重、资源变化、预算耗尽、CLI、两阶段休眠及面板历史快照。

其中真实受限工具产生了收益序列 **[1, 0, 1]**：首次读到 count=2；换题重复读同一内容；文件变为 count=3 后再次核验。第三次结论为 false，仍是新版本的真实否定观察。模型回复来自固定测试适配器，不调用真实模型。

未来承诺交接到既有休眠控制时保留最早开始时间；新输入会中止交接，就绪任务会阻止交接。临时控制记录不代表启动了正式生命实例。

完整功能回归共538项：535项通过，3项真实模型验收未显式开启而跳过，无失败和错误；其中本项新增35项通过。停止竞争检查曾发现锁范围过大的回归，已将协调锁缩到工具回执入账阶段，原停止矩阵与全量回归重新通过。最终冻结版本的源码稳定检查和正式实例只读比较均通过，结果见 `outputs/acceptance/development-t11.json`。前端8组检查见 `outputs/acceptance/thought-inspection-ui.json`，为组件交互测试，不是真实浏览器视觉验收。

## 能力边界

- 承诺目前只覆盖向控制者交付本地文件目标；不是任何自然语言承诺都能核验。最长单活动10分钟、最多3轮；长期指持久等待和恢复履约，不是无限连续推理。
- 截止审计发生在下一次授权运行循环恢复时，时间到了不会越过停止锁自动唤醒。忙碌、审批或资源不足可能导致违约，如实记录。
- affinity 为显式声明兴趣，不是已证实的内在心理状态；事实覆盖收益不是通用学习进展或主观满足。人格驱动的兴趣自动成长仍需独立数据与实证，不能从本项推出。
- 自主探索仍须显式开启原 exploration；启用 agenda 不会偷偷开启探索或补充预算。关闭 agenda 只关闭新登记和排序/测量策略，不自动解除已经激活的承诺。
- 取消未完成工作不能撤销已经发生的外部副作用。未知效果仍按原执行器对账，不伪造成功。
- 没有执行当前实例的部署、重启或唤醒；是否采用新版须后续显式操作。
