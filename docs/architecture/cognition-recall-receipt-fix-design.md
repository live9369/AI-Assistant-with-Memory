# 认知重复与保存回执修正设计

日期：2026-11-15。范围：native核心聊天与认知回流；不启用成长模块、不迁移旧数据、不操作正式实例。

## 问题与目标

现有认知去重把引文也作为内容，因此同一来源的引文片段变化可造成重复版本。复述可召回认知表示还会把旧认知再次包装成新来源。模型公开回复生成在事务保存之前，不能证明最终保存成功或未保存。

## 修改规则

1. 保留全部精确引文、来源有效性与账户域检查，再进行去重。
2. 对直接引用认知表示的 reported 提案，不新增认知版本；记录 suppressed_recall 及原认知引用。这只说明没有新增原始信息，不宣称新提案语义等同于原认知。新的 hypothesis/method 不受此规则吞并。
3. 同一认知主体、谓词、值、种类、有效时间、适用线索和同一来源相同，只有引文片段不同，复用仍可读的版本。不跨来源合并，不作模糊语义或人物身份合并，不把 held 升级为 accepted。
4. cognition.output_recorded 增加新建、复用、抑制计数，保留原 revisions 字段。失败事务不产生成功回执，重试幂等。
5. 聊天表达要求只回应信息本身，不提前宣称保存完成或未保存。后台在已接受请求的 cognition.output_recorded 记录存在后生成独立系统回执，同时用于聊天展示和后续显式历史。回执说明“候选”，不宣称事实已确认；旧事件缺少计数字段时不猜测。
6. 模型原始输出保持原样，不通过字符串替换改写它。系统回执提供实际执行依据；不能保证任意模型永不违背表达指令。

## 必要验证

只使用临时实例和替身模型：首次保存、同源换引文复用、纯回忆抑制、真正更正保留、不同来源保留、假设不被吞并、来源撤回拒绝、聊天实际回执及下一轮历史、失败不显示成功。复用既有经验回流和来源测试验证权限与确认历史。

## 已知边界

无法仅靠文本规则可靠判断任意两句是否同义。本版不增加模型调用，也不自动合并同义谓词或实体。正式部署需要后续单独执行，当前运行实例保持原样。
