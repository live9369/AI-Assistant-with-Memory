## 实际交付

新增 V4 严格输出协议，与旧 V1/V2/V3 并存。新增 continuous_exploration.py，使用现有 SQLite 事件和 artifacts 保存方向、每步理解、下一步、来源、概率选择及真实工具回执。方向跨独立请求延续；多个候选不再仅按最高分排序。等待有间隔，暂存及结束不自动重开；显式重开要求新可读来源与原因。分支保留父方向，切换使原方向冷却。失败/中断方向暂存。重复无进展会暂停，不继续派发工具。

选择使用人格、当前负载、近期经历关联、认知未确认比例、最近动机和可关联的关系可靠性；缺失关系明确标注，习惯仍未启用，habit_missing 明确为 true，不伪造指标。人格等因素也进入实际 LLM 输入。概率参数是未经校准的工程初值。

不再要求所有方向都具备文件验证路径；反思、创作、联系经历可以产生阶段理解，统一标为模型自评，独立验证为 false。工具仍经原有审批与 Executor；实际回执作为下一轮历史观察输入，不能当作外部状态始终未变的证明。探索完成只完成当前步骤，不把未核实理解确认为事实。

## 核心验证

38 项相关检查通过，耗时约 8 秒，含 8 项新循环核心用例；5 项原聊天组件检查通过，JavaScript 语法通过。使用临时 SQLite、替身模型、受控本地文件读取，没有真实模型调用。

新循环覆盖：产生两个反思方向；跨轮与重新打开数据库后承接；结束不自动重开；重复理解与方法暂停；撤回来源拒绝；概率归一及等待冷却；工具先审批再实际执行并记录回执；分支与切换；显式重开要求新增来源。首版还不能据此宣称真实模型一定能产生高质量自主思考。

## 使用

先停止实例，保存新版配置，然后按原 CLI 流程部署并启动；本次未执行下面命令：

```sh
python3 manage.py stop
python3 -m digital_life --data work/primordial00-first-wake exploration enable --mode continuous --interval-seconds 60 --max-activities 12
python3 manage.py start
```

查看：`python3 -m digital_life --data work/primordial00-first-wake exploration status`。
停止：`python3 -m digital_life --data work/primordial00-first-wake exploration disable`。
显式重开：`exploration reopen --direction ID --sources NEW_SOURCE_REF --reason 原因`。

## 限制

语义相似度与候选进展采用启发式，不能保证识别所有换句话重复；新理解绝不按字数变化认定已验证学习。复杂自动重开条件尚不执行。严格 schema4 路线显式不开放新版。概率和来源选择需要下一次最小真实验收再评价，之后才考虑长时间测试。旧探索记录没有批量转换；保留旧模式可供回看。
