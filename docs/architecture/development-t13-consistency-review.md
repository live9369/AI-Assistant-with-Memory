## 发现与修正

| 问题 | 修正与验证 |
| --- | --- |
| 检查点标志比底层证据强，部分结果仅核对总数 | 按每周期活动关联独立思考请求和实际工具回执，检查接受状态、工具名称、路径、内容哈希和真实读取结果；核对当前身份锚点及真实修复事件，禁止复用修复事件 |
| 进程存在不代表睡眠代次正确 | 将process_run、实际PID、退出记录、提交的sleep handoff及runtime_epoch逐项关联；重算哈希链仍不能掩盖代次矛盾 |
| 适应性摘要可与独立保存的实验数据不一致 | 比较两份摘要，核对概率范围、改善、无关情境保持、回退值，以及真实习惯事件中的回退和恢复active状态 |
| 收尾重开数据库失败会阻断停止动作 | 先写禁止唤醒锁并持久化controller停止，再重新打开runtime数据；使用故障注入验证重开失败仍保持停止 |
| 联合证据损坏时，脚本可能退出而留下旧通过结果 | 门控捕获证据读取/校验错误，写入当前失败结果及错误原因，刷新证据哈希，保持validating |
| 任务状态只凭通用passed可误标T13完成 | task_plan额外要求engineering_passed、long_horizon_passed、joint_matches_current_source均为true；反例验证缺一不可 |

数据库schema、LLM调用接口、生命活动权限和正式实例生命周期未因本轮复核改变。生产代码相对T12冻结清单的变化仅为task_plan完成门控；其余修正位于外部验收脚本、evaluation、测试和文档。
