# 第一至第四项详细实现设计

版本V0.1。目的：在不更新当前实例的条件下，形成可检验的活动、认知和学习闭环。保持既有V1任务、V2探索契约兼容，新增功能显式选择。SQLite事件与现有认知/学习表承担记录，不对运行实例做迁移。

## T01 基线与任务门控

冻结当前digital_life模块的SHA256、实际部署ID和身份，以及11项已通过认知题的题面和判断规则。基线只读，不复制活跃实例去并行运行。固定回归题保存在config/evaluation；进度保存在docs/plan/task-status.json。任务检查器校验ID、依赖、状态、设计和验收文件、证据状态及哈希。通过项不可仅靠修改status声称通过。活动运行记录自然增长，不使用活跃数据库整文件哈希作为源码冻结依据。

## T02 有限目标闭环

TaskLoop为显式配置的活动增加事件化轮次和验证条件。初版条件为受限工作区文件包含期望文本；路径必须相对且不得穿越、不得经过符号链接。输入是用户任务和可信验证器配置，输出是持久化观察、验证结果和下一轮或终态。

每轮独立request_key与parent，输入增加先前公开回应、真实工具回执和后续用户信息。工具成功先调用独立文件验证器，条件不满足继续新一轮；满足才完成目标。达到轮次、预算、期限上限时暂停，不伪称完成。ask/wait持久等待；显式resume提供新信息并递增input_epoch，旧结果保持不可变。重复结果不得重复推进；重开数据库后从事件恢复。stop/cancel、权限epoch和原执行链保留优先级。该协议不与探索活动混用。

## T03 结构化认知

显式开启的认知增强采用V3输出：原action/explanation，加cognition对象，包含claims、questions、predictions、plan。逐字段限制长度与数量，证据只能引用本次显式输入的证据/记忆引用或本次观察。LLM声明的“用户说过”须有精确引用，但引用匹配不代表语义蕴含已验证，因此保存为候选或已报告陈述，不作为现实真理。

同一subject/predicate维护认知修订与支持/反对证据，变化保留前版本。控制者可确认或更正；模型不能授予自己确认权限。疑问进入hypotheses，预测保留概率及核验规则，计划依赖必须引用先前步骤。新请求可读取明确选择的认知快照。未开启的旧任务继续V1；探索继续V2，拒绝版本错配。执行来源、证据撤销和停止状态在接受时再次检查。

## T04 记忆修订学习

第一版聚焦有控制者反馈的记忆修订：明确反馈及证据生成提案，固定目标原版本与新内容；自动创建评估试用，在两个独立临时数据库副本中比较原版和候选版。用至少两个不同检索问题和控制者提供的预期测量真实检索结果，记录命中/不应出现内容、样本和差值。候选必须有收益且无回归才能成为可批准项。无提升、有回归或数据缺失则拒绝/待定，不伪造成功。

采用需要控制者、正确提案/试验/评估关联、通过状态和目标版本CAS。新记忆修订追加，记录旧新版本。回退追加补偿修订，不能回滚整个生命数据库或抹掉经历。人格与价值不在本项自动修改范围。模型自述收益不作评估分数。提案创建、试验、评估、采用和回退均可追踪；独立副本一直禁止唤醒，无LLM或工具执行。

## 接口与验收

CLI提供task-loop配置/继续、cognition状态/确认，以及memory-feedback提出/评估/采用/回退入口；面板思考详情可看到V3认知与轮次输入，并显示审计事件。所有写操作有控制者和状态检查，不提供面板唤醒。

分项隔离：T01验证门控拒绝无证据完成；T02验证两步目标、错误结果、重复回执、wait/resume、超限、数据库重开与停止；T03验证V1/V2兼容、V3结构、伪造来源、候选不冒充事实、修订及计划依赖；T04验证原版/候选对照改善、回归拒绝、错关联、CAS、重复采用、补偿回退与无副作用。最后完整回归并复查当前实例仍是原部署。性能和人格效度不以本项测试代替。
