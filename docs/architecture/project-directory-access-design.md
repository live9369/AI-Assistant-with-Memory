# 指定目录操作实现设计

2026-11-15，实施中。

采用 OpenCode/Hermes 的文件工具分工，在既有原初00执行器内实现小型适配层；不迁入另一个完整 agent，避免出现第二套思考、会话和权限。现有四框架调研来源见 project-file-tools-review-v0.1.md。

第一版：目录列表、分页读取、文本搜索、新建及按旧 hash 修改文件；明确目录授权、撤销、自动允许或逐次审批。每次思考仍独立；工具结果和变更差异显式进入下一轮。root 账户才有系统动作权限。新增具名检查执行能力需真实命令边界，不以 cwd 冒充沙箱。

配置通过 CLI 写入事件，保存根目录真实路径、设备/inode、排除项、工具列表、自动允许选择和配置代次。资源 scope 随行动/审批固定，执行前再比较当前授权；撤销或换配置使旧行动失效。执行 worker 不持有数据库连接。

文件访问使用目录 fd 和 O_NOFOLLOW 逐段打开，禁止上跳/符号链接/隐藏路径/硬链接/特殊文件。实例数据、授权及发布目录不通过通用文件工具暴露。写入要求旧 sha256；空值仅用于新建；写前核对，临时文件落盘后原子替换单文件，保留操作日志及原内容。其他进程不遵循锁时不能承诺通用跨进程 CAS；检测到版本变化必须冲突，不覆盖已知变化。

旧 workspace 工具和原授权不改变。工具定义按需注册到已有表，无数据库 DDL。关闭/未授权时不向输入暴露项目路径和工具。

核心验证：真实 worker 新建/读取/修改、授权撤回、旧 hash 冲突、越界不写、工具回执进入下一次独立思考。只运行这些相关用例。正式启用目录以用户回答为准。
