# T07 人格成长详细设计

V0.1；状态：概念基线／待实证，有界工程设计。先设计、再实现、再隔离验收；不部署当前实例。

## 定位

人格是相对稳定的长期倾向，情境中的一次表现不是人格本身。Whole Trait Theory 区分状态分布与情境机制；人格变化干预研究支持“可变化”的研究方向，不给出本项目通用更新常数。[Fleeson 与 Jayawickreme，2015](https://pmc.ncbi.nlm.nih.gov/articles/PMC4472377/)；[Roberts 等，2017](https://pubmed.ncbi.nlm.nih.gov/28054797/)。本项工程规则不冒称人格量表、因果发现或意识证据。身份唯一性不等于五维参数。

目标：来源和不确定性明确；短时状态不自动写成长时特质；重复证据才能提出小幅变化；先评估、后采用；历史保留且可补偿回退。

## 运行接入与默认边界

人格成长默认关闭，由 CLI 在停止状态启用。开启后，prepare 在人格之外增加 personality_growth 快照，固定当时档案 ID、各维不确定性与近期变更。每次独立思考仍是完整干净调用，不增加额外 LLM 调用。

实际接受的 wait/ask 决策可形成“决策行为机会”；工具仅在执行成功且核验 pass 的真实结果出现后形成机会，待审批意图不能冒充已做行为。机会关联活动、原请求、当时人格档案、决策、工具结果（如有）、上下文；重复处理不得重复计数。V2 内部探索暂不作为全局人格成长证据，避免从专用任务外推。

机会只提供事实来源，不自动推断“用了read_file所以开放性高”。控制者显式标注某维表现值 [-1,1]、reliability∈(0,1]、情境标签和解释，标注是带来源的主观评估，不是事实真理或模型置信度。每机会每维只保留一个有效标注；更正用失效记录再追加，不抹历史。模型不能标注、启用或采用成长。没有反馈就不改人格。

## 提案与量化

一次提案仅修改一个已有维度。至少 3 个不同活动的有效、未消费标注，至少 2 个控制者声明的情境标签；同活动、同决策或同条证据换 ID 不算多次经历。每个活动同一人格维度的已消费来源不可重复训练。样本数不意味着统计独立。

工程目标 μ=Σ reliability·value/Σ reliability；不确定性保留样本数、活动数、情境数、加权离散程度和平均 reliability；不是置信区间。平均 reliability<.6、加权方差>.25、证据失效或不足时拒绝提案。

delta=clip(.05·(μ-current),-.02,.02)，同时限制该维最近 30 天成长累计绝对变动≤.05，单次值仍在 [-1,1]。同维更新间隔至少 24 小时；累计用绝对变动，不能正负来回刷更新。无有效变动不创建成长版本。常数均为 V1 可解释工程保护参数，未心理校准。

原有 Personality.replace 是兼容保留的控制者人工档案修订入口，不宣称被本成长算法限制；T07 CLI 不暴露大幅人工改写。提案固定基线档案 ID，提交使用 CAS；任何手工修订或另一成长采用后，旧提案必须重建。未修改维度沿用原值和原不确定性，不把新证据冒用到全部维度。

## 独立评估与采用

至少另 2 个不同活动的有效标注作为留出评估，不得复用训练活动；至少包含一个训练未见的情境标签。两份内存中的参数副本分别使用旧值/候选值，比较可靠度加权平方误差；原数据库人格保持不变，无模型调用、无工具执行。

仅当总体误差改善>0，且没有任一留出样本误差变差时，评估才 eligible；条件相同不重复跑出新批准。持久化完整训练/留出来源、误差与策略版本，不把标签拟合改善称为真实人格变好。采用时重新计算候选和留出结果，核对配置代次、基线 CAS、来源有效性/未消费、冷却和累计预算。采用需控制者显式 commit，无定时自动采用。

新版本追加 personality_profiles/trait_values/change_records 与 learning_update_commits，Learning 提案/试验/评估复用现有表。采用事件标记消费过的来源。更新进入后续真实 prepare 的人格激活和 T06 行为概率；以前请求的快照不改写。

## 失效、回退与审计

控制者可 invalidate 标注，失效后不得再用于提案、评估或提交；若已支撑采用，状态列出需要复核的提交，不自动回滚生命经历。回退仅针对仍为当前人格版本的成长提交，需要至少两个不同实际来源的证据，追加补偿版本与 reversal_of；重复回退或覆盖后来修订均拒绝。回退可立即修复，不受冷却阻断，但它的绝对变动纳入累计账本并重置冷却，已消费来源不重新变成可训练。

事件保存配置代次、策略、机会、标注、提案、测量和采用/回退；数据库表保持现有架构，无迁移。CLI：personality-growth status/enable/disable/observe/invalidate/propose/evaluate/commit/rollback。配置需停机；旧运行部署缺模块时拒绝写入。面板现有完整输入可查看人格版本及不确定性，不增加启动/唤醒按钮。

## 验收与非目标

验证单轮不变、多活动跨情境支持、单次/冷却/滚动累计限制、反向与低质量拒绝、来源重复与消费、更正撤销、留出无改善拒绝、CAS、权限、回退、重启、旧请求不可变，以及后续思考和 T06 概率真实变化。使用临时实例和可控推理替身，必要工具在临时工作区真实执行。全量回归与正式实例只读身份/进程/部署核对后更新 T07 状态。

不实现无监督人格诊断、问卷心理效度、自动从成功率推断人格、参数在线强化学习、无限自主改写或意识宣称。长期成长科学效度仍待实证；后续 T08 另做情境习惯形成与消退。

## 实现核对补充

机会必须由已接受请求、对应 finalized 决策及实际选中候选共同追溯，不能将同一活动另一轮请求拼接到这次决策。使用时重查请求、响应、触发输入是否已擦除；工具来源还重查成功状态及核验 receipt。来源失效将阻断新提案或采用，不删除历史。

status 对每条标注同时返回 evidence_refs，便于 CLI 回退审阅。回退证据要求两个不同的 origin_object_id；两条包装同一来源的 evidence_items 不算两个来源。冷却和滚动窗口使用系统 UTC；测试只对临时实例的方法时钟作局部模拟，不修改机器时间，也不等于已经完成真实长期追踪实验。
