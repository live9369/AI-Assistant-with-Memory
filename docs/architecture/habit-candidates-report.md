# 习惯候选学习交付报告

日期：2026-11-15。状态：设计、实现、必要隔离验证及正式部署完成；只开启候选采集。

## 已实现

自动采集实际行为，并按账户、来源、完整短任务、完整动作及参数分组。同一组合在3个不同活动中出现，形成待确认候选；候选本身没有行为权重。

控制者确认后，重新核对3次实际来源与动作，登记到既有习惯模块，以0.3工程初值开始影响匹配候选的概率。确认是一次明确的人工认可，不把3次重复伪造成3次正反馈。已有抑制、恢复、明确反馈、消退和审计机制继续使用。

采集开关与习惯生效开关分开。收集可以单独开启；确认前必须停止实例并显式开启既有 habit-learning。拒绝可以在不足3次时提前执行，保留记录。确认/拒绝具有版本检查和幂等键。

采集只覆盖root或原控制者，确认后的账户习惯仅在原账户表达。新增候选不提供权限，不自动添加新的工具动作。工具必须有成功且核验pass的真实回执，未知或待审批不算合格样本。候选采集的来源不可用时记录skipped日志，不丢弃已接受的核心回应或工具回执。正式实例不回填旧历史，不为验收制造正式习惯。

热路径按已有(instance_id, source, source_event_id)唯一索引的source前缀定位特定组合，单组收集3条即转待确认，不每轮重扫历史。候选列表一次最多100组，原始审计继续保留。没有新增模型调用、没有提高预算或削减特征。

新增9项核心测试通过（2.633秒）：重复与幂等、确认后实际概率提升及抑制后移除、情境不合并、拒绝及旧版本冲突、来源撤回、非root过滤、工具真实成功/未知区分、必须停止及显式开启、采集失败不丢核心回复。

## 使用

```sh
# 查看自动积累的候选；不调用模型
python3 -m digital_life --data work/primordial00-first-wake habit-learning candidates

# 有值得保留的候选后，先正常停止并等运行器退出
python3 manage.py stop
python3 -m digital_life --data work/primordial00-first-wake habit-learning enable
python3 -m digital_life --data work/primordial00-first-wake habit-learning confirm-candidate \
  --candidate CANDIDATE_HASH --expected-revision REVISION_ID \
  --reason '已审阅具体情境和三次实际行为，认可保留此倾向' --key UNIQUE_KEY
# 或用 reject-candidate 拒绝；确认完成后按原CLI流程启动
```

停止后可用 collect-disable 关闭采集。已经确认的习惯若不再合适，使用既有 inhibit 命令立即移除影响；不是删除经历。不要把关闭采集误认为撤销已经生效的习惯。

## 当前边界

- 最多200字的完整任务文本精确匹配，动作参数也精确匹配；wait/ask的reason不同也不自动合并。长任务暂不纳入，避免自动截断扩大情境。
- 学习的是已有候选动作的倾向，不直接学习措辞、温暖程度、表达风格，也不是通用技能训练。
- 后续强度变化仍依赖既有明确反馈，不自动把工具成功视为“做得好”。
- 宿主带部署/排除标记的验收和自主探索不采集；未标记的普通用户测试话语不能保证自动识别为测试。
- 普通账户的完整学习适配未完成，不借本项放开原全局学习限制。人格成长保持关闭。
- 0.3和三次是沿用的工程初值，不是人类习惯形成的科学阈值。

主要文件：`application/habit_candidates.py`、`habit_learning.py`、`engine.py`、`entrypoints/growth.py`；测试：`tests/test_habit_candidates.py`。
