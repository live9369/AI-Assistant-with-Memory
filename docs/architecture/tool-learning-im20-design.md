# IM20 正式材料准入与封存准备设计

2026-11-10；准备范围，无模型调用，无实例访问。

依据冻结 TL-LOOP-0.1 §9及补充、TL-EVAL-0.1 Q11材料包与Q10独立标签要求、storage §5/7、IM17材料边界。Q11允许明确标注的合成模板，但同源改写不能增加独立case，且当前开发agent不能自给正式标签。因此本项不凭程序扩写2800题冒充正式材料。真实独立作者/原材料及两评审/裁决尚未提供，正式有效材料数保持0。

本项实现独立目录 evaluation/im20 下离线准入工具：只接收已独立制作的结构化材料清单；对来源簇、答案共享键、DEV永久排除来源/家族、模板相关性、三/一查询、k=5、合格相关集合、逐主张支持/范围/未知/重大错误例、权限/时序和版本证据做失败闭合校验。synthetic允许准备，不能由声明自动推断自然独立性；必须保留家族并报告限制。

固定装配按八类TARGET及五类RETENTION顺序，各类别case_id排序，每100项一批；仅全量有效材料可形成实际28批，缺材料时不造空批。每case三repeat，两臂用固定seed 20261109交错顺序。输出仅装配计划，不派发任务。

权限投影用显式字段白名单，学习/接纳仅获learning_input、单查询请求仅获对应query_input；真值和盲化映射不投影。投影不是OS身份隔离，正式部署仍须独立所有者/运行账号及拒读证明。角色登记需独立性证据，两个字符串或同一模型不视为人员就位；本次roster固定false。盲评仅定义待填协议，不伪造输出/评审。

交付准备状态JSON、严格校验器和有意义变异测试、源与工具SHA256准备摘要和缺口报告。摘要为准备快照，非独立正式签署/accepted。冻结规范不修改，公共实现不修改。不运行全局verify，不触及work实例。设计后经锁transition到designing、implementing；专项验证完成后因独立材料/人员缺口保持blocked，不完成IM20，不启动IM21/22。
