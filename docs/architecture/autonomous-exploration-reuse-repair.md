## 机制修改

新增 `application/exploration_evidence.py`，负责具体验证路径提取、保守问题身份匹配及共享回执索引；修改 `application/exploration.py` 的上下文、接纳、复用与资源变更后重开逻辑。`infrastructure/tools/workspace.py` 在授权读取内记录稳定资源元数据。`application/engine.py` 采用 exploration-v2 指令并收紧探索检索条数。没有扩大工具权限。

未变化资源跨问题共享原回执；再次读取先复用，再重复则暂停。资源改变或来源权限撤回会使缓存失效，准备好的上下文也会重检。过期回执只出现在历史摘要，不能作为新的 resolved 依据。确有资源变更时可沿原问题 ID 新开修订，整体活动预算保留。详见 [1.2 契约](autonomous-exploration-contract-v1.2.md)。

候选 verification 必须映射到已有安全相对路径的 read_file/list_files，无法执行者单独过滤并记录原建议、原因，有效同批候选继续保留。该检查证明可执行而非证明证据足够；不承诺识别全部语义重复。量词别名保守合并，数字、实体、否定不同仍可独立提问。共享证据允许对同一文件提出不同问题。

冻结时工作区已有 Chat、公共回复记忆、混合检索及 CLI 变化全部保留，新基线记录当时实际集成版本，不回退到旧 Engine。[机器基线](autonomous-exploration-baseline-v1.2.json)冻结 116 个文件、4 个接口；schema V2 和 M01–M16 正式定义不改。
