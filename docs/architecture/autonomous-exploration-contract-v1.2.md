## 候选接纳与问题身份

候选 verification 必须出现安全、已存在的相对工作区路径，能映射到 read_file（最多 64KB）或 list_files；最多提取两项计划。解析器保守支持 ASCII 路径及 notes 目录表达，不声称覆盖全部自然语言。内部 event/evidence/result ID 查询或网络搜索不在能力内。映射到文件只证明可执行，不能证明该文件足以回答问题；质量仍需人工评判。

无路径的候选单独过滤，其他有效候选继续接纳；保留完整模型输出，并写 candidate_filtered 原因。精确文本及同资源的保守量词变体复用 canonical question ID；不采用宽泛相似度合并，保留数字、实体、否定差异。语义改述仍可能漏判，因此不能把文本去重数当成语义重复率。提示中提供已有问题与评估，要求沿用原问题措辞。

已 resolved／abandoned 的同一问题仅在成功回执对应资源的元数据确实变化后可转回 candidate：ID 不变、resource_revision 加一、visits 归零、旧评估从当前状态清除，历史事件保留。活动总预算不重置；来源必须仍可读。外部资源消失不会自动重开。

## 共享证据与观察边界

read_file/list_files 在实际授权工具调用内记录读取前后的设备、inode、mtime_ns、ctime_ns、size；只有稳定且 succeeded/pass 的原始回执才进入资源索引。索引和每次新上下文构建仅检查元数据，不偷偷读取文件内容，不制造新的观察证据。跨问题复用保留原始 evidence、result、receipt 与来源权限。list_files 只缓存该目录项列表，不推断子文件内容未变化。元数据校验不是密码学内容一致性证明，也不消除恶意并发文件替换的原有工具竞态。

上下文提供有界的共享回执与已有问题，每个完整对象通过大小筛选；不截断回执文字。模型生成的记忆标示为推断。发送前及接纳前检查来源权限与共享资源元数据；变更则拒绝旧上下文。资源发生变化后可授权重新观察。

若模型仍请求读取未变化资源，首次将原回执附到当前调查而不派发工具；若当前调查已附过同一 result，再请求则暂停，理由 repeated-unchanged-observation。真实读取、复用和暂停分别保留事件。该规则限制重复 I/O，不等价于证明模型产生了新信息，也不改变 M04/M08 人工判据。
