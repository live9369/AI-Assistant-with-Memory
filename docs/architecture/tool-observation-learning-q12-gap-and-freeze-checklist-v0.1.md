## 2 现阶段可确定的存储约束，仍不是DDL

1. 原证据/回执只引用既有不可变身份及具体版本，定位跟随该版本和视图；不以多份正文产生独立来源。
2. 提案、认知决定/内容版本、表示/映射和交接工作各有自己的业务身份，不共用一个success行。
3. 内容版本和原引用、交接义务、表示版本可双向追溯；独立项与互依赖组的唯一性和原子边界分别规定。
4. 幂等身份必须覆盖实例、用途、固定输入/基线、目标与方法版本等其业务语义；同键异义拒绝。具体组合需逐接口定稿，不能套用一个万能hash。
5. 工作状态更新带预期版本/有效租约/代次及预算账本约束；超时扫描不得抢写新工作器结果。
6. 控制屏障、当前权限/源版本和传播义务不是纯索引水位；正确恢复必须考虑镜像外的可信排除记录。
7. 正常历史不可静默覆盖；明确删除按合法范围优先，审计不能重复保存未获准正文、秘密hash或错误日志。
8. SQLite、blob、索引和外部服务的原子边界不同，设计须分别写提交/确认/补偿/恢复规则，不宣称分布式整体原子。
