# T09 人物与关系认知详细设计

V0.1；概念基线／待实证；有界工程设计。先设计、再实现、隔离验收；不部署当前实例，不重建身份、记忆与历史。

## 定位与边界

人物“叫什么”、是否同一实体、与自身什么关系、在什么条件下可依赖，以及是否有系统权限，是五件不同的事。实体链接文献区分匹配与不确定匹配；信任模型区分能力、善意、正直及情境和风险。[Fellegi 与 Sunter，1969](https://www.tandfonline.com/doi/abs/10.1080/01621459.1969.10501049)；[Mayer、Davis 与 Schoorman，1995](https://journals.aom.org/doi/abs/10.5465/amr.1995.9508080335)。本项借鉴概念，不声称实施完整统计实体解析或验证人的真实心理信任。

## 默认与身份保护

默认关闭，控制者在停止、没有活动运行进程时启停。register 显式登记人物及来源，生成独立 entity/actor ID，不根据同名去重或合并。人物为未外部验证的本地登记，不能自动变成系统控制者。当前 controller、self_actor 与 identity_anchors 不修改；名称或关系称谓不改变权限。

姓名规范化仅用 Unicode NFKC、大小写和空白归一化辅助检索，不做编辑距离或同音推断。多个候选始终 ambiguous；一个候选也只是本地 unique_candidate，非现实身份鉴定。没有实体合并 API，不改写旧 claim-subject、记忆人物或历史外键。

## 别名与关系称谓

alias 为某 actor 添加带 scope 的别名，至少两个不同来源的证据；一个别名可指向多个人，保留歧义，不以最后写入覆盖。指定 scope 有明确别名绑定时使用该 scope 的候选，否则使用全局姓名及全局别名；scope 默认 global，聊天可用 chat:会话ID。别名失效追加记录，原表和历史不删除。

relate 添加带证据的称谓，例如父亲/朋友/同事；至少两个来源。称谓是控制者审阅的陈述，不证明法律亲属身份，不授予 grant。来源撤销或失效后不再作为当前关系输入，但保留旧记录。

## 进入真实认知

prepare 构造 relationships 快照：配置及登记代次、实际触发 actor、当前输入字面提及的人物候选、别名范围、关系称谓、条件信任与未解决分歧。仅做登记名称的字面识别，不宣称通用命名实体识别、任意代词消解或语义实体匹配。

T03 开启时，结构化 claim 的 subject 通过本模块按当前 scope 查候选。只有证据审阅的明确别名绑定且无歧义时，才可用其本地 entity ID；仅姓名唯一仍不自动绑定，歧义、未审阅或未知标签创建本次活动局部的 ambiguous/unresolved claim-subject，同活动同标签复用，跨活动不凭同名自动合并。既有信念和实体保持不变，陈述仍为有来源的候选，不因实体链接变成现实事实。

每次思考仍独立调用；来源、别名或关系修改使旧快照拒绝派发或采用，不拿当前值改写旧输入。

## 条件信任的量化

维度支持 reliability、ability、benevolence、integrity，各自按 actor+domain+condition 独立记录；不同领域和维度不平均。condition 只允许 source 精确匹配与 task_contains 字面子串，空条件表示该域内全条件；不能执行任意代码。

trust 操作由控制者给一条有来源的 0/1 观察与解释。每个格子同一证据来源只计一次，换 evidence ID 包装无效；失效后也不靠包装重新计数。默认 α=β=1，实际有效正/负证据分别加到 α/β，estimate=α/(α+β)。这是控制者标注的平滑频率模型，不是心理校准概率；无有效观察时 missing，不把 .5 先验伪装成测量。保存数量、来源、条件和方法版本。

来源可为已存在的对象或不可变制品；核对实际对象、内容哈希、擦除和直接记忆读取权限。多个证据 ID 包装同一 origin，或无 origin 时指向同一制品哈希，不算不同来源。来源数不表示统计独立或事实真实。

T06 仅消费实际触发 actor 的 behavior/reliability，按当前活动条件挑选最具体匹配格子，再以最新修订破同具体度平局；不把提及人物当成操作者，不用别的域替代。启用 T09 后由 relationships 快照供值，关闭则保留 T06 既有兼容读取路径。

## 破裂与修复

负观察使相应格子有未解决分歧，关系可标记 disputed；不把其他领域数值清零。正观察不会自动宣布整体关系修好。

repair 需要控制者显式确认，且该格子最近一次负观察之后至少有两个不同来源的有效正观察。修复事件引用这些观察；旧负证据保留在估计中，不恢复成满信任。仍有其他格子未解决时，整体继续 disputed。已 dormant/ended 的关系不因信任反馈擅自重新激活。

新负观察会再次打开分歧。失效或撤去修复支持后，当前投影不再把该修复当作有效。invalidate 仅追加失效记录及解释，不抹历史；这是控制者更正陈述，不作为独立的关系修复证明。

## 一致性、存储与接口

操作采用幂等 key；信任与修复写入需要 expected_revision，使用模块全局代次作保守 CAS，避免并发覆盖。配置代次独立，人物/别名/称谓/信任/修复/失效推进登记代次；活动局部 subject 绑定不推进全局代次。

利用现有 world_entities、world_entity_aliases、social_actors、social_relationships、social_trust_assessments/evidence 及关系维度表，额外信息记录不可变事件；无 SQL 迁移。当前投影重查来源，不能拿历史缓存估计替代有效证据。更新关系投影不修改身份认证、审批或执行授权。

CLI people-relations status/enable/disable/register/alias/resolve/relate/trust/repair/invalidate。启停需停止；旧运行部署缺模块时拒绝写入。面板完整思考详情保存 relationships 候选、条件信任和来源；旧请求不回填。

## 验收与非目标

隔离验证同名不合并、别名歧义和撤销、scope 分辨、受保护身份、关系称谓无权限、信任域/条件隔离、证据去重、CAS、两条新证据修复且保留旧坏记录、其他分歧不被抹掉、来源撤权/擦除、T03 实际 subject 绑定、后续独立思考与 T06 概率影响、旧快照/重启/历史保留。全量回归及正式实例只读保护核对后完成 T09。

不实现现实身份认证、自动实体合并、任意自然语言人物识别和指代、欺骗检测、法律亲属认定、心理信任测量或所有关系生命周期。本项是可审计、有证据的受控工程基线。

## 实现核对补充

启用后，只有本模块带来源观察参与新的频率投影；旧 scalar trust 行保留，不能反推出不存在的正负次数。关闭时回到既有路径，但排除本模块的 assessment 行，避免失效的管理投影回落成旧版“最新信任”。不自动迁移旧实体或把旧 scalar 当作新证据。

全局登记代次是保守一致性策略：无关人物修改也可能使旧请求失效，当前不优化到逐实体依赖。别名、称谓与信任当前投影均重查来源；历史表行保留，不拿未清除的缓存行冒充当前有效陈述。

字面候选最多 20 项。T03 中，仅姓名唯一不会自动绑定，必须另有经审阅的当前 scope 或全局别名绑定；不做实体合并或重新归属既有信念。关系修复仅表示本格子分歧经有限新来源审阅，不代表消除全部风险、修复法律关系或测得心理信任恢复。
