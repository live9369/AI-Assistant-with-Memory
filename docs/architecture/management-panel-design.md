| 属性 | 内容 |
| --- | --- |

## 1 问题与目标

现有页面只有令牌、任务输入、审批编号和JSON输出。后端已有大量基础能力，但缺少可分页的管理查询、可读的过程详情、配置表单、健康快照和日志检索。不能将后端验收视为完整管理端已经完成。

本轮将面板做成五个日常工作页面。用户不需要手工复制审批编号、理解原始SQL或直接编辑配置JSON，仍然可以在明确授权后管理实例。实际执行继续由既有活动引擎承担。

## 2 页面与交互

| 页面 | 首要信息 | 操作 | 空白／异常状态 |
| --- | --- | --- | --- |
| 总览 | 实例、唤醒锁、停止状态、任务／审批数量、模型摘要、最近事件 | 刷新、保持停止、进入待办 | 未配置、无任务、未检查健康分别显示 |
| 活动与审批 | 状态筛选、任务列表、活动过程、工具参数、审批有效期 | 保存任务、查看过程、取消、批准／拒绝 | 过期、取消、已决定的审批不能再次操作 |
| 模型配置 | 当前版本、本地／远程接入方式、地址、模型与预算 | 载入模板、离线校验、保存新版本、显式检查清单 | 不显示或接收真实密钥；配置被别人更新时拒绝覆盖 |
| 健康 | 各维度状态、原因、检查时间和时效 | 明确触发重新检查 | 未检查和证据不足是unknown，不填绿色健康 |
| 日志 | 时间、类别、等级、事件摘要、关联活动 | 条件检索、分页、查看脱敏详情、导出 | 没有匹配项、权限失效、请求失败可区分 |

桌面端使用左侧导航与内容区域，移动端改为紧凑导航和单列布局。状态有文字与颜色，按钮有加载态和禁用原因，表单有标签，弹窗支持键盘操作。原始JSON仅放在按需展开的详情中。

连接令牌只放在当前页面内存，不使用URL、cookie或localStorage。断开连接清除令牌与已展示数据。连接后可选15秒自动刷新；仅发只读查询，不检查模型网络、不重置正在编辑的表单，也不关闭审阅中的弹窗。

## 3 代码职责

```text
web/index.html + styles.css + app.js  视图、表单、交互与请求状态
                  ↓
entrypoints/http.py                  认证、HTTP约束、静态资源、错误响应
                  ↓
application/management.py            管理查询、分页、界面DTO与管理操作协调
                  ↓
既有 Engine / Policy / configuration / HealthMonitor / Control
                  ↓
SQLite运行库与独立控制库
```

不在浏览器中实现权限判断的最终裁决，不在HTTP层复制生命活动状态机，不引入第二套任务队列。不改动数据库模式；管理界面依托既有记录与事件生成可读视图。

## 4 接口契约

统一返回JSON；列表返回items、limit、next_cursor、has_more。列表采用稳定游标，查询值参数化；limit默认20或50、上限100，日志导出上限500。查询词长度、状态、时间和游标校验失败返回422。

| 方法及路径 | 用途 | 副作用 |
| --- | --- | --- |
| GET /v1/overview | 汇总、运行控制与模型／健康摘要 | 无 |
| GET /v1/activities | 状态／关键词筛选、分页 | 无 |
| GET /v1/activities/{id} | 活动、步骤、思考元信息、动作与状态过程 | 无，不返回完整思考输入 |
| POST /v1/events | 幂等保存任务 | 保存待办，不思考、不执行 |
| POST /v1/activities/{id}/cancel | 校验当前修订后取消 | 使用既有取消语义 |
| GET /v1/approvals | 审批列表及有效状态 | 无 |
| GET /v1/approvals/{id} | 工具、参数、范围、摘要、期限和可操作性 | 无 |
| POST /v1/approvals/{id}/decision | 带修订与参数摘要批准／拒绝 | 记录决定；批准进入执行队列，不启动进程 |
| GET /v1/model/configuration | 当前配置版本、接入参数及密钥变量是否存在 | 无，不返回密钥值 |
| GET /v1/model/templates | 随包交付的模板 | 无 |
| POST /v1/model/validate | 离线验证表单 | 不联网、不推理、不保存 |
| POST /v1/model/configuration | 带当前版本保存新配置 | 默认离线；要求停止状态，无活动进程 |
| POST /v1/model/probe | 对已保存配置明确检查模型清单 | 可联网但不生成；保存检查结果 |
| GET /v1/health | 最近健康快照及过期标记 | 无，不因刷新而新增检查记录 |
| POST /v1/health/check | 明确触发本地多维检查 | 保存观测；不连接模型服务 |
| GET /v1/logs | 等级、类型、活动、时间、关键词筛选与分页 | 无 |
| GET /v1/logs/{seq} | 脱敏详情 | 无 |
| GET /v1/logs/export | 按同样筛选条件导出JSONL | 只读；最多500条 |
| POST /v1/control/stop | 幂等保持停止 | 不回退重启，不解除锁 |

保留原状态、指标、记忆管理等已有接口。健康GET由“刷新即写入”改为只读快照；模型保存默认离线，网络检查独立为显式操作。这些行为变化在操作文档说明。

## 5 并发、授权与审计

- 审批提交携带expected_revision和expected_arguments_hash；在同一事务内重新核对修订、期限、参数与关联活动状态。过期、取消、已经决定和参数变化返回409，不创建新授权。
- 取消携带expected_revision；模型保存携带expected_configuration_id。页面打开后记录有变化时返回409并提示刷新，不能静默覆盖。
- 新建任务与停止保留幂等键；页面重试同一次提交复用键。操作中禁用重复点击，服务端仍是最终门禁。
- 不增加解除WAKE_DISABLED、启动Runtime、运行工具或在面板填写API密钥的接口。
- 决定、取消、停止、配置、清单探针及健康检查使用现有事件记录审计，不将令牌、Authorization或密钥值写入日志。

批准仍有业务含义：如果另有获准运行的工作进程，队列里的动作可能被执行。面板不能把“批准不会启动进程”解释成“批准永远不会执行”；锁定的正式实例仍不可执行。

## 6 健康、模型与日志的真实性

健康页面分别显示healthy、stressed、degraded、critical、recovering和unknown；快照超过有效期标记过期。没有检查记录时不隐式扫描，不因进程登记存在就宣布健康。

模型“配置有效”“清单可访问”“生成质量通过”是三种不同结论。表单验证和默认保存均离线。远程检查需要已明确启用的远程配置及环境变量，只读清单不被冒称真实推理验收。缺少凭据、清单接口不支持或服务不可达时明确报告。

日志默认展示事件摘要，不批量暴露任务正文、记忆、思考输入或工具输出。详情与导出必须脱敏：敏感键、已知控制令牌与已配置API密钥值不能进入响应。用户内容使用textContent呈现，禁止插入为可执行HTML。等级由事件类别推导，未声称已有完整外部日志系统。

## 7 HTTP与静态资源边界

只监听127.0.0.1。所有数据API要求Bearer控制令牌，检查Host和Origin；拒绝非法方法、超长载荷及无效JSON。静态资源采用固定白名单，不允许路径遍历。设置禁止缓存、禁止嵌入、内容类型和CSP约束。

错误使用稳定状态码和结构：403认证／权限、404不存在、409记录变化或状态冲突、422参数／配置、503内部服务异常；错误中不返回数据库详情、堆栈或供应商错误正文。

## 8 验收计划

| 层次 | 必须验证 |
| --- | --- |
| 管理服务 | GET不写入、不联网；分页筛选；关联范围；空记录；异常游标；过期与旧版本阻断；脱敏 |
| HTTP | 认证、Host／Origin、静态资源、方法、载荷、错误码及导出 |
| 浏览器 | 五页切换、令牌连接／断开、任务保存、审批／拒绝／取消、表单校验／版本保存、健康刷新、日志检索／详情／导出 |
| 可访问与布局 | 标签、键盘弹窗、加载／空／失败态、桌面和移动端无页面横向溢出 |
| 整体 | 原完整回归、真实本地模型、安装包资源与管理页静态资源；正式实例逐文件及唤醒锁不变 |

浏览器和HTTP服务仅绑定新建临时实例，使用临时浏览器资料目录，不复用用户浏览器登录数据。真实远程API不参与本轮；模型清单检查在测试中使用替身或隔离服务。
