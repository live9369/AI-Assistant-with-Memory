# 习惯学习接入：自动积累候选，确认后生效

2026-11-15。用户已确认：先做习惯学习，暂不启用人格成长；自动积累候选，由控制者确认后影响行为。

## 目标与边界

补上现有 HabitLearning 必须先人工登记才有观察的问题。复用原有形成、抑制、消退、概率评分及权限机制。不把重复当作正确，也不把工具执行成功当作效果好。

首版只处理 root / 原控制者的实际外部输入，同一来源、完全相同的短任务文本（最多200字）、完全相同的行动及参数；不作模糊情境识别，不从工具文本、记忆、模型说明中提取权限。wait/ask 的 reason 也是参数，不自动合并措辞。普通用户的学习适配另行处理，不开放全局私人习惯。

## 流程

1. 单独开启候选采集；此时既有习惯学习可以保持关闭，候选没有行为影响。
2. 每次已接受的实际决策记录一份情境与反应样本。工具动作必须等真实结果成功且 receipt verification=pass；未知、待审批和失败不算发生过的合格动作。部署探针、探索及带宿主排除标记的合成验收不纳入日常习惯。
3. 同一组合至少3个不同活动形成待确认候选；同活动多轮或重放不重复计数。不自动回填旧历史。
4. CLI列出候选及真实来源。root 在停止实例后，提供候选当前版本、原因和确认命令；宿主重新核对原请求、接受结果、被选中动作、源输入及工具回执。
5. 确认表示控制者认可这些重复行为值得保留，才登记原有习惯并赋予首版0.3初始倾向。记录单独的 reviewed-adoption 事件，不伪造三条用户正反馈，也不证明心理自动性。旧习惯学习必须已显式开启。
6. 后续继续使用原有明确反馈更新、抑制、恢复和消退。候选拒绝保留审计，不自动激活；已拒绝组合不会因重放变成新候选。确认与拒绝采用版本检查和幂等。

## 存储与接口

复用 runtime_events：habit_candidates.configured、sampled、decided；采样事件用源活动和组合hash做幂等键，组合分组按来源及精确内容，候选状态由事件投影产生。

CLI扩展 habit-learning：collect-enable、collect-disable、candidates、confirm-candidate、reject-candidate。确认要求 --candidate、--expected-revision、--reason、--key。状态返回 collecting、样本数、pending/confirmed/rejected、动作、线索和来源引用。

采集默认关闭；正式部署后只开启采集，不预先确认任何候选，不开启人格成长，不为验收制造正式习惯。

## 核心验收

临时实例和替身模型验证：重复3次形成候选但不影响概率；同活动不重复；确认后下一轮进入原行为评分；不同来源或任务不合并；拒绝不生效；撤去来源时拒绝确认；非root不采集；工具无真实回执不计数。只做相关测试，不跑长期或全量。
