# 聊天核心问题修复 V0.2

日期：2026-11-17。根据正式实例最近12轮聊天，优先修复核心业务。

## 本轮交付

1. 原生普通活动默认不设累计token、工具次数、总尝试次数与整体时长上限；使用显式budget_enabled=false表达，不用很大的数字假装无限。仍保存实际调用和用量记录。单次网络/工具超时、请求重试边界、输入容量与服务商限额独立保留。配置页可重新开启本地活动预算。
2. 已有活动继续按原快照与限额执行，不补额度、不自动重放暂停任务。严格学习协议及共享学习分配仍保持原有限约束，不经此设置旁路。
3. 每轮提供精简“自身运行说明”：实际模型路由与独立调用机制、各模块明确开/关、当前活动额度模式、配置页能力与受限项目入口。让模型能据已知设置直接回答，不拿缺失字段猜开关。
4. 对源码检查提供准确模块入口，要求先处理用户当前范围，避免两次列目录再找到兼容包装。可以查证的问题继续读取；普通闲聊不主动扫源码；完成后形成结论。有限模式停止时，显示已完成步骤、最后成果及未完成项。
5. root在聊天中明确用引号为实例指定称呼时，记录真实来源与授权的称呼事件。它不改变instance_id、人格、账户或模型路由。新称呼进入后续输入、页头与配置页，不依赖每轮恰好召回那条聊天。人工配置页的新身份锚点优先于更早称呼。已有明确命名记录仅在CLI更新时一次性承接，不猜测其他关系。
6. 调整表达规则：先回答具体问题，只在相关时解释限制；普通对话保持自然和人格倾向，技术问题根据实际运行说明回答，不每轮重复意识声明。

## 验证与范围

先用临时实例与替身模型验证：超过四轮工具后仍可形成结论；有限模式仍停止并有总结；停止/撤权仍有效；新旧活动预算不混；称呼跨多轮与重开可用，普通账户与引用示例不改名；开关明确关闭时可见；源码入口准确。只做相关核心检查，不启动长期测试或全套性能专项。

真实生成的自然程度不能由替身证明。正式更新保留身份、人格、所有历史与账户，仅按用户授权把后续普通活动默认模式改为不限累计预算，并承接此前已指定的“霖铃”。人格成长继续关闭。旧暂停任务不自动恢复。

## 验证结果与启用记录

- 临时实例以6次真实文件工具读取、7个独立请求形成最终结论；保留13条思考/工具预算记录，未用大数替代无上限，也未减少来源或权限判断。
- 有限模式仍按原额停止，并给出已完成操作、目标路径、最后公开进展和未完成说明；不额外花一次模型调用来掩盖预算停止。
- 相关63项检查最终覆盖通过；其中一个普通账户用例在安装账户后沿用旧Store的列缓存，夹具改为重新打开Store后单项复验通过。有限资源调节的旧测试显式启用有限模式，不降低其原有断言。
- 两次真实模型调用仅使用虚构身份与固定配置问题，无正式记忆或历史。首次暴露“root误说成根实例”和把总尝试数误称额外重试，修正运行说明后最终确认通过。最终回复能明确说人格学习关闭、每次独立进程、活动累计预算不限以及root账户的面板入口；约14秒是模型调用观察，不是整套系统所有场景的时延承诺。
- 正式实例更新前无活动在执行；备份后承接此前明确命名为“霖铃”的记录，持久化后续活动budget_enabled=false。12轮交流、34条记忆、3条认知、2份人格版本和15次既有请求数量不变，人格成长仍关闭。

证据：outputs/chat-core-fixes/application.json及real-model-check.json。没有自动重放旧的暂停任务，没有给旧活动补额度，没有在正式实例提交验收消息。日常回复速度仍受模型服务耗时影响；本轮通过提供准确入口减少无效查找轮数，不承诺所有回复即时完成。
