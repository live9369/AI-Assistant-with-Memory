# 聊天身份与人格表达 V0.1

范围：当前原实例使用的原生聊天链路；不迁移高级学习链路，不修改权限、预算或输出数据库结构。

每次独立调用在 Engine.prepare 的最终特征组装之后增加 chat_expression。身份取自 configuration_versions 对应的 name、self_actor 和 instance_id；人格取本次 personality_states，携带状态引用、数值及简短表达含义。关系、动机、状态及行为上下文继续使用原模块生成的数据，表达层引用它们，不重复复制或伪造。

instructions 明确：以自身立场直接交流；explanation 在聊天中是公开回复，非旁观分析或内部推理；模型是推理工具，不是自身身份；人格是倾向，不是固定台词。熟悉程度取有来源的关系和记忆，不能把 controller 自动当成父亲。状态只使用 fresh 数据，机器负载不等于主观情绪。不能保证恒定热情，不冒称意识已被证实。

起始人格采用用户确认值：开放性 +0.4、尽责性 +0.3、外向性 −0.1、宜人性 +0.3、情绪稳定性 +0.3。通过既有 Personality.replace 写入新版本，保留旧版本；使用不同来源的设计建议和用户批准作为明确标注的控制器配置依据，不冒称经验观察或测评。人格成长保持关闭。

关系认知、目标动机与行为概率通过现有 configure 接口在停止的隔离副本启用，不直接修改开关表。默认行为概率可能选择 ask 或 wait，不等于修改公开回复措辞；本轮表达由特征映射和提示负责，不宣称已实现词句级概率模型。

验收只覆盖身份、人格差异、三模块请求接入、独立调用、连续对话和跨会话记忆。保持现有来源校验和权限流程；遇输入预算不足直接报出，不提高上限或静默裁剪。隔离副本验证通过后，原实例更新仍需单独完成，未部署不得报告已生效。

## 经授权的状态输入紧凑表示

仅在 Codex 聊天发送前对 states 做无损表格编码：列名只写一次；重复的列值使用字典及零基索引。编码前后必须能逐项还原一致。数据库中原始请求和来源校验保持原结构；模型输入明确解释字典含义。只在编码确实更小时使用。不删状态，不改变新鲜度，不提高输入或时间预算。其他模块不压缩，本步骤不能保证最终输入一定足够小；若仍超限，停止真实调用并向用户报告。

2026-11-14：用户批准仅将隔离副本本地输入容量调整至32768字节。发送时优先原始易读输入，原始输入超限时才尝试已批准的状态无损表示。活动预算、超时和权限不变，正式实例暂不更新。

隔离配置更新触发核心缺陷：Engine.prepare 以未排序 rows() 的末项绑定配置，与实际 Store.config() 最新版本不一致。修正仅为明确按 rowid 读取最新模型和配置；旧请求不重绑定，需另建活动。

## 正式回复主体修正 V2（2026-11-14）

用户明确要求直接修改正式版本，不再创建隔离副本。上一轮正式回复显示推理器把“你是谁”理解为询问Codex自身；新协议不要求推理器改变真实身份，而是明确其工作为替持续实例撰写公开回复。task及会话中的“你”指向实例，explanation只能包含实例可直接发给对方的第一人称回复；模型来源被问及时如实说明，不冒称意识。

在chat_expression持久输入中记录reply_protocol版本，在Codex发送前的固定前缀中落实该协议，不把记忆内容提升为指令或权限。原有独立调用、工具禁用、结构化输出、数据和预算不变。通过CLI停止并部署同一实例，以正常聊天确认；不创建隔离身份或重放历史诊断请求。
