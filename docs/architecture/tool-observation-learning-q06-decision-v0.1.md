## 1 核心问题与裁决边界

M14提交提案，不等于M03应当接受；M03保存候选，不等于认可其为当前认识；M03接纳有范围内容，也不等于M04召回表示已完成，或该内容永远为真。

Q06决定：哪些条件足以进入某种接纳路径，不能通过时返回什么，怎样合并／替代而不抹掉历史。Q07再决定跨模块保存与恢复，Q08决定如何召回，Q09细化失效，Q10—Q11确定评测，Q12整体冻结。本文不提前发布运行状态机、编写新验证器或赋予自动确认权限。

## 3 现状核对与方案比较

现有`CognitiveUpdates`会保存带引文的held候选，确认入口重检版本、来源和控制者，并追加接纳版本；接纳仍标注为控制者审阅，不等于外部证明。现有`CognitiveExperience.save`校验提案类型、来源、幂等与预期版本，保存shadow经验；有效测量与unknown已区分。这些是可复用的局部门控，不是本文通用经验接纳、合并及范围政策已实现。

| 方案 | 问题 | 裁决 |
| --- | --- | --- |
| 新材料、较高信心或正收益就覆盖旧内容 | 混淆来源、时间、收益和事实资格；容易丢失历史 | 不采用 |
| 任何知识都只能人工逐条确认，或一律不接纳 | 保留现有审阅边界有必要，但作为永恒统一方案会忽略可检查的有界自动处理 | 不作为唯一未来机制；没有已授权规则时仍按现有门控／候选路径 |
| 类型化证据要求＋预先授权的有限规则／现有复核＋显式版本决定 | 可区分候选、有限接纳和未决冲突，保持所有权 | 采用；规则缺失时不默认自动接纳，不在本轮创建实际授权 |

## 4 三层结果必须分开

1. **提案处理结果**：本次请求被接受处理、候选持有、暂缓、拒绝、版本冲突、重复复用或被控制条件阻断。它描述本次交接。
2. **认知内容状态**：候选、有范围接纳、被后续版本替代、撤回等；由M03权威决定记录及版本关联表达。正常修订不原地重写过去。
3. **当前使用资格**：此时此用途能否用这份内容，取决于其认知状态、适用范围、来源、权限、版本及冲突等。曾被接纳不保证现在可用。

这些是语义区别，不是本轮冻结的枚举。“历史版本被接纳过”与“当前有效版本”必须同时可表达；M04只生成指定版本的表示，不取得内容资格决定权。来源撤权造成不可用不等于判定内容为假，也不等于删除原历史。

## 5 统一接纳检查：先有资格，再决定操作

M03独立检查Q05提案及其依赖，不能只信M14的ready_for_handoff。检查可以引用可验证结果，但须明确其方法、基线、来源和适用范围。

| 检查 | 必须满足／明确的内容 | 不满足时 |
| --- | --- | --- |
| G01 请求与执行许可 | 实例、提案生产者、类型／目标所有者、当前执行许可、用途与处理预算适用 | 拒绝或按Q03阻断／停止；不为补齐认知自动解锁 |
| G02 结构与未知 | Q05必需信息完整，未知／缺失／不适用有明确表示；具体主张及操作意图可识别 | 结构不合格拒绝；可补的材料按有限暂缓处理，不擅自填默认值 |
| G03 来源与定位 | 当前有权读取的原证据、原版本、视图和定位可核对；派生链可追溯 | 不接纳无出处内容；发生撤权／失效时立即阻断相应使用 |
| G04 含义与支持 | 来源确实支持所声称的有限命题，区别原文、转换、推断／假设；必要前提与局限可见 | 缩小的替代方案须显式记录，或候选／暂缓／拒绝；引文匹配不是充分条件 |
| G05 目标与可比性 | 对象、属性、时间、条件、单位和覆盖可比；existing目标及预期版本符合当前基线 | 版本冲突返回重评，不自动覆盖；不可比内容不能被合并或当反证 |
| G06 已有认识与冲突 | 检查提案涉及的认识及显式依赖；已知支持／反证与来源相关性不被忽略 | 冲突可保留，必要时限制受影响范围；不按最新／副本多／语气强选赢家 |
| G07 类型政策与权限 | 有适用于该内容类型、变更方式和风险／用途的已授权接纳规则或既有复核结果 | 无匹配政策不得默认通过；保留候选或请求明确复核，不能自己生成许可 |
| G08 局部性与操作结果 | 实际接纳内容不超过证据／批准范围，改动及保留项清楚；同一提案幂等，返回对应决定与版本 | 不把部分通过报成整体接受，不重复计算学习收获 |

不要求查遍整个库并证明全世界无矛盾；必须声明检查覆盖，核对已知相关内容及依赖。缺少关键材料与存在关键反证不能用“未发现冲突”掩盖。相关依赖造成其他认识需要重评时，给出显式理由和对象，不自动连带改人格、价值或行为策略。

## 6 类型化接受政策

本节给出接受所需条件，不给没有依据的0.8信心或固定样本数阈值。涉及的“预先授权规则”必须实际存在、可定位且适用；本文只设计这种入口，不启用任何规则。没有规则时保持现有控制者门控／候选策略。

| 内容／建议类型 | 可以接纳的范围与条件 | 应当候选／暂缓／拒绝的边界 |
| --- | --- | --- |
| 有来源的直接报告 | 所有G检查通过，指定工具契约、解析／定位可核对，且有覆盖此类型的授权规则／审阅；限于“来源S在给定范围报告X” | 不能因内容取出就升级为现实对象绝对状态；契约／对象／时间含义不清时保留候选或补证 |
| 明确转换／计算 | 原输入可用、转换规则／单位／适用前提已授权且可核对；结果标为派生 | 未声明规则、单位不明或转换丢失限定时不能接纳为确定结果 |
| 解释性的事实认识 | 需要该领域／任务可核对的支持及反证处理，符合当前复核政策；接纳也要带范围与不确定性 | 仅有模型解释、准确引文或控制者认可的语气不足以声称外部已证明；没有适用复核机制保留候选 |
| 情境／方法经验与一般规则 | 必须明确条件、支持材料、相关性、例外和检查范围，且有适用规则／复核；若声称方法效果，关联合格评估 | 不从一次读取成功推出“总是有效”；不把有很多副本当多次独立支持；缺效果时不自动捏造可靠性 |
| 原因／机制判断 | 需要明确因果假设、适用方法与相应证据审查；符合政策才可有范围接纳 | 仅先后／相关不足；可以保留原因假设，但不能将其作为已核验原因 |
| 学习效果统计 | 合格测量报告可重算，协议、来源／版本、样本与独立性说明适用；按原量尺接纳其统计含义 | 正收益不能使无依据事实变真；零／负收益也不自动使内容错误；无合格报告保持unknown |
| 冲突标注／已知局限 | 支持“存在这些不相容主张／局限”的依据完整，可接纳冲突关系及使用限制 | 接纳冲突标注不等于两边都作为当前事实；不能擅自生成赢家 |

候选保存不是失败，也不是范围较弱的事实确认。保存假设时应保持假设性质。接纳某份含unknown收益的有限内容是可能的；但如果该内容本身所必需的对象、范围或依据未知，则不能用“收益可未知”越过内容条件。

“这类经历对本实例有什么意义／用途”的评价可以引用已有意图、价值与状态及实际结果，作为有处境限制的经验判断；它不同于外部事实正确性。不能用个人偏好代替事实核验，也不把客观gain等同喜欢程度，或借接纳经验直接修改由其他模块拥有的人格／价值。实际效果未测时仍保持unknown，不强求将个体意义包装成科学定律。

模型生成与规则校验可属于同一工作，但同一模型重复自检不是独立外部证据；不同模型读同一来源也不会制造独立观察。对复杂语义的复核不能简化为再跑一次模型直到它同意。具体复核材料、能力要求和验证方式由Q10—Q11补齐。

## 7 接受、候选、暂缓、拒绝和复用怎样区分

| 决定（概念名称） | 适用情况 | 是否生成当前可用认识 |
| --- | --- | --- |
| 有范围接纳 | 完成适用检查／复核，内容、状态、范围及政策明确 | M03保存对应认知版本；当前用途仍须检查有效性，不等于M04表示已完成 |
| 候选持有 | 请求和来源可记录，但解释、概括或资格尚未达到接纳条件 | 否；保存候选身份／原因，只供明确候选分析用途 |
| 暂缓处理 | 缺项可界定、依赖／复核／基线尚未齐备 | 否；给出补什么、谁负责和Q03的期限／退出，不无限等待 |
| 拒绝本提案 | 结构无效、来源不符、操作越界、主张超出支持或无合法处理路径 | 否；有理由记录拒绝，不等于证明原内容为假或旧认识必对 |
| 版本冲突退回 | 目标已经变化，旧提案的前提不再适用 | 否；针对新基线另行重评，不隐式改提案重试 |
| 重复复用／无需内容变更 | 同一提案或相同范围内容已经处理，且依赖／当前权限检查允许复用 | 复用原决定／版本，不新增认知接纳次数或收益；说明当前使用资格可能已变化 |
| 控制／权限阻断 | 用户停止、锁定、撤权、期限／额度等不允许本次继续 | 否；按Q03保留真实进度，不派发或自动清锁 |

同一提案身份带不同内容须作为冲突／非法重用处理，不能按幂等成功返回。重复查询原决定可看到“当时接纳”的历史，但不得将已经失效的结果重新宣布为“当前可用”。无权者不得通过复用接口获取此前私密结果。

### 允许限定接纳，但不能偷换命题

M03可按已授权规则提出或接纳原命题的明确受支持子范围，必须同时记录请求范围、实际接受范围及原因。若从“现实库存10”变成“文件S报告10”，主张目标／谓词已经改变，不能把它报成原提案通过；应拒绝／持有原提案并关联新的候选或经授权的新提案。

一份提案有多个独立变更时，逐项决定并报告整体未完全通过；互相依赖的变更不能只接受造成不一致的一半。Q06决定语义约束，批量事务、补偿及保存顺序交Q07。

## 8 怎样合并：合并依据或表示，不制造更强结论

合并由M03负责，须有对象与语义范围对齐、当前来源／资格可核对及明确的版本政策；M04索引去重／摘录合并不能代做认知合并。

| 材料关系 | 允许的处理 | 禁止的处理 |
| --- | --- | --- |
| 同一提案／原证据重复，范围相同 | 关联原决定或追加不改变证据身份的关联记录；无需内容版本时不造新认识 | 副本越多越可信，重复接纳或收益累加 |
| 内容等价、范围相同，新支持依据合法 | 检查来源相关性，按政策形成保留所有依赖的新支持／内容版本，或有理由地关联 | 自动将新ID当独立证据，切断较严格权限依赖 |
| 内容相容但对象／时间／条件不同 | 分开保存并建立明确关系；必要时形成另有支持的概括候选 | 合并为无条件“始终如此”，或把不同对象的值平均 |
| 同范围不相容 | 保存冲突及各方依据，限定受影响用途；足够新依据后另作修正决定 | 拼成一个看似一致的句子、投票选真或平均值折中 |
| 一方范围是另一方子范围 | 保留各自范围和支持；可在有依据时收缩／分割原概括 | 以局部支持悄悄扩大整条规律 |
| 别名／身份尚未消歧 | 暂不合并对象，保留待核对关系 | 仅凭名字或相似措辞合并人物／事实 |

每个业务内容有自己的权威版本链；同一对象可以有不同时间或条件下的多条认识，不能用单个“最新值”抹平。合并涉及多个旧身份时保留它们及新关系，不让旧引用无声指向另一含义。派生内容的可读范围不能因为融合而比原依赖更宽，具体来源与依赖传播交Q09。

## 9 怎样修正、替代与撤回

1. **时序补充**：t0报告7、t1报告10可同时成立。新增相应时段／观察报告，不认定t0错误，不倒改旧时间。标为“最新观察”也要说明截至哪个已检查时点和范围。
2. **纠正原理解**：可核对原回执为10而旧解释是7时，针对错误解释形成有理由的新版本；保留旧解释与更正关系，不能伪造旧版本从来是10。
3. **收缩过宽认识**：反例否定“所有记录为7”，并不支持“所有记录为10”。明确撤回／限定受影响范围，保留真正受支持部分。
4. **未决冲突**：不足以确定赢家时，不强行替代；受影响当前视图应注明冲突，不能继续无提示给出原单一确定结论。不同来源“报告了什么”仍可分别成立。
5. **证据撤回与资格失效**：按源政策阻断不合格继续使用；如果有其他有效支持，是否继续有范围持有须按明确政策核对，不能因一个源失效就随意判整条认识为假，也不能忽略唯一来源已无效。
6. **补偿／恢复**：新撤回／替代被证实不当时，由M03基于当前来源和版本作新的恢复／修正决定，不倒放历史数据库或自动复活旧权限。

替代须明确替代哪份内容的哪部分及基线、理由、支持／反证、实际范围和新版本。旧提案基线失效先重评，不能“已做完分析”为由覆盖新版本。正常变更保留旧记录；显式隐私擦除仍按Q02/Q09处理，并不承诺永久保存被要求删除的正文。

更正版本提交后，旧版本不能再无提示进入当前认识用途；保留旧记录也要保留其与新决定的关系。**这不是要求删除所有旧记忆，而是要求历史查证与当前使用分开。** 具体召回、已准备输入、缓存和失效传播由Q07—Q09落实；原始回执不改写。

## 10 决定记录与交接责任

M03的每次实质决定应能说明下列语义信息；具体字段名、载荷与枚举在Q12统一，不替Q05四类M14产物添加越权写入字段：

- 决定身份、实例、处理的提案及其版本／指纹，目标与预期／实际基线。
- 决定者、接纳政策／复核依据、决定时点和检查所用来源／规则版本。
- 本次结果及理由；实际接纳内容／范围、保留候选／冲突的部分和未解决项。
- 新认知版本或无需变更时的既有版本引用，替代／合并／撤回关系；未成功时不能伪造版本引用。
- 支持／反证与依赖、来源相关性／独立性限制、当前视图所需的适用条件。
- 请求或传达给M04的表示需求及后续关联；这里不是M04表示成功回执。

M14记录自己收到的决定引用，不能修改M03决定；M04依据指定认知版本生成表示，不能把候选改写成当前事实；M17保证支持的技术持久化，不能以一次COMMIT替认知批准。

提交前重新检查控制、权限、配置及版本。已提交决定真实保留，后续停止不伪装成“从未发生”；尚未完成的接纳不能因为分析完成就越过停止提交。认知成功而表示失败按Q02/Q07记录交接未完成，重建同一版本不再接纳一次或新增学习收获。
