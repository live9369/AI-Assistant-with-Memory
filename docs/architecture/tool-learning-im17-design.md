# IM17 开发材料与机制覆盖设计

版本：V0.1；日期：2026-11-09；状态：材料制作，不是执行验收。

本项依据 TL-LOOP-0.1、Q10、Q11，制作公开 DEV24 与可封存 MECH 制作清单。先划清材料边界，再登记逐项来源、夹具、预期和证据要求；不实现评测执行器，不调用模型，不操作任何生命实例。

## 材料结构

`config/evaluation/tool-learning-dev-v0.1.json` 保存八类各三题的公开合成学习输入、三类固定查询、开发可见标签、相关集合、错误例和来源簇。三个同家族变体不能冒充独立正式样本；整个合成家族永久排除 TARGET/RETENTION。标签作者为当前开发 agent，未独立复核，不是正式真值或双盲评审。

`config/evaluation/tool-learning-mechanism-manifest-v0.1.json` 保存逐裁决、逐未来题面、Q10二十类检查、48项并发分支和既有G1的原111项/继承125项材料与场景映射。精确引文、行号及来源摘要用于静态核对；每题分别给出输入变异、注入边界、预期终点、必需观察和TL指标。未来题面直接保留原文，不把一个概括性的“覆盖全部”当实体题面。Q01/Q02没有编号的未来题面，另以逐裁决正反证明计划覆盖，保留其库存示例来源。

## 执行与封存边界

每个需要执行的 MECH条目登记三个重复ID，重复不能增加独立质量case。线程与跨进程矩阵各24分支（两入口×三控制×四时点），分别三次；跨进程不能用线程测试冒充。既有G1的原27机制、24停止、60材料全部逐项保留，另登记1.1新增6场景与1.2新增8场景，继承场景并集65加材料60，其六个历史失败及冻结源码对照只作既有证据，不标成本次结果。

所有轨迹、运行结果与计量值均未产生。夹具状态为 planned；文件存在只证明材料存在。IM18负责评测库/执行器/聚合，IM19负责执行MECH/G1，新运行未完成前 blocked_before_start。材料包允许做静态完整性检查；它不能解锁模型消费、删除或实例操作。

封存应固定本材料两份JSON的字节摘要、全部引用源、协议/执行器/夹具/代码版本、重复ID清单、故障计划、时钟及磁盘/时间管理限额。后续修改产生新版本和新封存，不能就地改题后追认旧运行。未实现的执行器、夹具、价格/货币预算、独立正式材料及评审保持明确缺口。
