# T05 目标、动机与内部状态详细设计

版本 V0.1；状态：设计基线，工程验证范围见验收报告。先设计，再实现；不部署现有实例。验收范围为 V1 工程策略，不代表科学效度已经证实。

## 目标与边界

目标是“要完成什么”；动机是“当前愿意投入多少”；内部状态是“当前运行条件如何”。本阶段将三者接入现有活动、预算和独立思考流程。健康仅指系统运行健康，强度仅指工程上的投入倾向，不等于情绪或主观体验。人格、认知、记忆、关系与习惯的高维行为概率留在 T06，本阶段排序不声称是行动概率或科学校准的心理指标。

## 输入与量化

控制者为活动声明 importance（重要性）、expectancy（预期收益可达程度）、cost（预估成本）、risk（风险），均为有限的 0—1 数值，默认分别为 .5、.5、.5、0；缺省是明确的工程先验，不是观测。alignment 是价值维度 ID 到 0—1 相关程度的映射，缺省维度为 .5。按当前价值档案权重加权，保留档案与权重引用。人格与认知不伪造为已校准分数。

自动观测来自现有 StateCollector：磁盘可用字节、SQLite 完整性、恢复协调标记、队列深度。引用观测、有效期和证据。缺失、过期、质量非 valid 的必需状态意味着暂缓，不能当作健康。磁盘最小余量默认 64 MiB，可由控制者显式配置；队列负载以 depth/(depth+10) 归一化，只惩罚而不全面停机，保证能够排空队列。

## 竞争、动机与停止规则

score = clamp(.35 importance + .25 value_alignment + .25 expectancy + .15 urgency - .20 cost - .20 risk - .10 load, 0, 1)。urgency=clamp(1-remaining_seconds/600,0,1)。这些系数是 V1 可解释工程策略，尚待实证，不冒称科学界统一参数。按下述 intensity 降序、due_at 和 job ID 稳定打破平局；剩余预算真实影响投入顺序。

动机 intensity=score×剩余预算比例；persistence=剩余预算比例；satiation 固定 0，未验证目标完成不推测满足。预算以已保留 token 和尝试次数保守扣减，不能误当真实账单。保留 token 不足一次 4096 token 思考、尝试耗尽、活动或目标期限到达、时间预算耗尽、取消或目标/活动终态、不支持的活动状态，都禁止新思考。低磁盘、损坏或待恢复、缺失状态暂缓，不自动取消或谎称成功。队列项保留，控制者可调整输入或显式处理；T02 的目标验证仍独立负责完成判定。

execute 和 commitment_due 等已授权工作维持原有租约顺序，不因目标评分越过审批。只对到期且可领取的 think 作竞争。关闭功能时完全沿用 FIFO。

## 运行流程与接口

1. 默认关闭；CLI 仅允许控制者在停止状态切换配置；活动权重只在尚未准备思考时设置。
2. process_one 在状态缺失或距过期少于 5 秒时刷新真实状态（TTL 30 秒）；空队列不采集，重复阻断不重复记录竞争事件，避免轮询无限放大历史；随后，同一事务内筛选可领取任务、评估并领取指定 job，沿用现有租约令牌与代次。
3. prepare 再次检查，写入 motivation_states 与 goal_regulation.assessed 事件，完整解释快照进入独立请求 goal_regulation 字段。历史请求保持不可变。
4. 调用推理器之前检查配置代次、活动有效性、预算和状态新鲜性；检查失败不调用模型。已有预算预留不重复计算本次额度。LLM 获得显式快照，每次仍为干净独立调用，不依靠供应商会话。
5. 旧目标、身份和记忆保持原样；新策略只追加事件和动机行，不重写历史。利用已有表，无 SQL 迁移。

CLI：goal-regulation status / enable / disable；enable 接受 --min-disk-bytes；prioritize --activity ID --features JSON文件。状态返回配置及最近评估。禁止模型自行授权或修改价值档案。新 CLI 在旧运行版本上拒绝写入不支持的功能。面板已有完整思考详情自动展示该输入字段，无需增加部署/唤醒按钮。

## 验收与限制

使用全新临时实例验证：排序实际改变首个调用；成本/负载/价值影响；预算/期限/取消/终态停止；缺失/陈旧状态和健康阻断；配置代次；未启用 FIFO；权限、参数校验；数据库重开和外键；全量回归。模型替身用于可重复的控制路径测试，不能宣称验证了真实模型心理行为。对当前实例仅只读比对身份、运行代次、活动进程和部署，不做更新或测试输入。

## 存储与兼容说明

配置、控制者特征、竞争、评估使用现有不可变事件与内容哈希制品；动机使用现有 motivation_states。评估中保存目标 ID、策略版本、每个加减分项、价值档案/权重 ID、状态观测 ID、预算和配置事件 ID。不借用 goal_activation_records 的 probability 字段把确定排序伪装为行为概率；不构造不存在的模型版本或来源修订。暂无批量 SQL 分析视图，后续可从这些可审计快照派生。

投入目前影响任务选择顺序和显式推理输入，不自动提高 token 上限、不替换 T02 核验器，不生成自主目标；单次思考仍保留 4096 token 的既有预留口径。长期饱足变化、学习系数、心理效度、通用目标依赖图及长期公平性尚未由本项验证。单实例串行调度保证一个思考作业被领取；已有 lease 机制继续防止过期工作者提交。
