# 自主选题真实测试报告

日期：2026-11-14。结果：核心流程通过，选题质量有限。

## 测试方式

使用原初00既有实例和当前 Codex 模型，不预设探索题目，不插入候选问题，不强制选择，不绕过审批。最多五次活动、最长十五分钟；两项自选方向结束后提前关闭自主探索，实际共三次调用。原聊天和健康维护继续运行，身份、记忆与历史保留。

启动前没有未完成方向，近期经历也已被处理过，因此调度器本来会等待。本轮如实记录用户允许“自行选题测试”的新指令来触发探索，没有修改发现记录或伪造新生活经历。这不是无外部触发的自发启动验证。

## 实际过程

| 顺序 | 系统实际行为 | 评价 |
| --- | --- | --- |
| 1 | 根据近期经历提出“成功回执能支持多大范围的结论？”和“自主探索何时值得继续，何时适合停下？” | 确实自行生成两个方向，但都受近期测试内容影响 |

两项方向各推进一步后结束，没有分支、调用工具或新增实际观察。没有反复重开已结束问题，没有调用失败或重试。这里的结束并不代表观点已被独立验证。

## 对照目标

- 自行提出多个方向：通过。
- 人格、动机等因素进入概率选择：通过，可查看实际因素、候选概率与抽样记录。系数仍是未经校准的工程初值，不能据此证明人格影响强弱合理。
- 从一个方向结束后选择另一个：通过。没有实测中途换向。
- 连续多步深入、新观察驱动修订、分支：本轮未出现，不能算通过。此前预设任务测试证明过多步承接，但不能代替自主选题质量验证。
- 发现与当前生活或任务相关的新问题：表现一般。两个题目都围绕系统测试和规则说明，更多是已有说明的归纳，没有出现明显的新探索成果。

## 原因与后续重点

当前选题从最近32条活动记忆中取最多8条可读经历；不纳入模型回复，但没有专门区分工程验收、执行状态回执与日常交流。本轮输入中，近期合成验收记录和 Action result 标识占据较多位置。模型因此围绕测试与证据规则出题，尚不能据此判断它在更丰富日常经历下也会如此。

后续应优先整理“哪些经历进入选题”：保留所有原始记录与来源检查，让工程测试记录默认不作为日常探索主线，工具回执在需要时连到其实际内容，而不是只给成功状态和标识；同时兼顾近期交流、未解决问题及当前动机。该建议未在本轮实施，没有删除或改写记忆来美化测试结果。暂不强制增加探索深度，也不提高预算。

## 耗时与状态
