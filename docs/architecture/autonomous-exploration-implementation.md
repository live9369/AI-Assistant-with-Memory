## 1 本次授权与范围

用户在报告交付后明确要求“开始修改吧”。本次实现探索协调、多轮独立思考、持久问题、观察反馈、预算及停用机制，补充隔离测试和交接说明。没有部署、启用或唤醒正式实例，也没有使用真实模型开展自主探索实验。

首版完成的路径是：

```text
授权运行中的 Runtime 空闲
  → 检查探索配置、间隔与活动总额
  → 从可读经历发现候选问题
  → 保存问题、来源、验证方法及预期收益／成本估计
  → 选择候选问题并建立内部活动
  → 提议读取工作区，经既有授权链执行
  → 保存观察和原始回执
  → 新建独立请求评估证据
  → 模型评估为解决，或继续／休眠／达到预算停止
```

独立推理请求之间不继承供应商会话。连续性来自系统的持久状态和显式输入。

## 2 设计落地与对原提案的调整

采用已有 `runtime_events` 加不可变 artifact 保存探索配置、问题快照、活动绑定、观察和评估。没有新增 SQL 表或更改 schema 版本，也没有修改生成的数据库资源。问题以最后一次快照为当前投影，历史事件继续保留。

这是现有持久机制的显式复用，不是把尚未接入的表当作已完成的能力。模型请求沿用 `thought_requests`、`activity_steps`、`thought_request_inputs` 和预算表。当前事件投影每次读取历史，适用于有限规模首版；大规模运行前需要检查点或物化投影和负载测量。

问题与活动独立：一个问题可跨活动及运行世代继续；一次活动内可包含多个思考请求，每个请求仍有独立尝试。普通外部任务保留原 V1 行为，本版没有把所有任务改为探索循环。

## 3 实际接口和记录契约

主入口：`digital_life/application/exploration.py` 的 `Exploration`。

| 接口 | 职责 |
| --- | --- |
| configure | 控制者设置启用、活动总额、轮次及间隔；切换配置世代，取消旧探索活动 |
| status | 只读返回配置、用量、调度状态和问题；不启动推理 |
| tick | 已运行进程的空闲检查，原子创建内部发现／调查活动 |
| context、check_inputs | 构造显式探索上下文，并检查记忆来源是否仍可读 |
| validate_output、accept | 校验模型提案、引用及动作语义，持久化候选和评估 |
| observed | 将工具回执接入后续思考，按结果 ID 去重 |

事件 payload 均带 `version: 1`：

| 事件 | 内容 |
| --- | --- |
| exploration.configured | enabled、max_activities、max_rounds、interval_seconds；事件 ID 为配置世代 |
| exploration.question | 问题 ID、内容、验证方法、证据引用、父问题、深度、状态、访问次数、到期时间和关联活动；后续可附评估或停止理由 |
| exploration.bound | 活动、配置世代、discover／investigate、问题 ID、最大轮次和下次到期时间 |
| exploration.observed | 工具结果 ID、证据、回执、执行状态及已有结果字段 |
| exploration.assessed | 请求 ID、结构化模型评估、`model-assessed-not-independently-verified` 标记 |

问题 ID 是大小写折叠、空白规范化后的问题文本 SHA-256。相同问题不会重置已有状态或访问次数；这不是语义去重。

问题状态实际使用 candidate、investigating、dormant、resolved、abandoned。配置取消、失败或恢复后暂停的活动，其调查问题可转入休眠；达到访问上限后不再选择。

## 4 模型输出与来源语义

普通任务继续使用 V1；探索请求显式选择 V2。V2 在 action、explanation 之外要求 exploration：候选问题列表、disposition、assessment 和 evidence_refs。候选问题含 question、verification、expected_gain、cost 和 evidence_refs。

发现阶段只允许 `wait` 配合休眠处置来提交候选，不能直接执行外部动作。调查阶段只允许 `read_file`、`list_files` 继续观察，或 `wait` 结束／休眠。声称解决至少必须引用显式上下文中的工具观察，但“引用了证据”不保证模型解释正确。

Ollama、llama.cpp、remote_chat 和 codex_cli 均按请求选择输出 schema。旧任务结构不变；没有执行真实供应商调用。

内部活动使用 internal 通道、self_actor、internal-trigger 证据和 internal 动机；不会把系统自己提出的问题编码成用户给出的事实，也不写入虚构的用户关系事件。原始工具回执与模型解释分开保留。

## 5 多轮、恢复和终止

- 探索请求键为 `thought:<activity>:<round>`，轮次对应独立 activity_step；后续请求通过 request_parent_id 指向前轮请求。
- 重试保留同一个请求及新 attempt；新观察创建新轮次，不修改旧请求包。
- 观察提交时增加 input_epoch，并在同一事务中记录观察、关联问题证据和下一次 think 工作。
- Executor 已提交成功回执、Engine 尚未消费就崩溃时，可从已有结果补齐观察，不重放工具动作。
- 新运行世代可以为已提交观察创建下一轮请求；旧世代已准备但未完成的请求仍遵循原来的保守恢复规则，不自动冒用旧请求。
- 配置停用／重设取消旧探索活动。推理期间取消或更换配置，返回结果只记录为 stale，不产生新动作。
- 读取成功只表示获得观察；目标和活动须经后续评估才结束。未知或失败观察会暂停；模型作业失败也暂停，避免一直占住运行状态。
- 人格、长期价值和权威信念不会因模型自述自动重写。resolved 是探索问题的模型评估状态，不是独立事实核验通过。

## 6 当前预算与选择策略

每次启用默认最多 12 个活动，可设 1–100；发现与调查都占额度。每活动默认最多 3 轮，可设 2–3；最后一轮用于评估，要求继续观察时转入休眠。每请求最多 3 次尝试；每活动预留 tokens、尝试和工具次数都有边界。token 限额沿用现有预留计数机制，不等于精确计费实测。

默认最小活动间隔 300 秒，可设 60–86400 秒。问题休眠默认 300 秒；单问题最多进入调查 2 次。候选问题最多保存 256 个，父问题链深度最多 3，每次输出至多 4 个候选。

候选以 `expected_gain - cost` 排序，同分按 ID 排序；两项来自模型估计，没有宣称是实测学习进展。人格与价值进入推理上下文，独立的长期兴趣学习及实测信息收益评分仍待后续实现。

发现会显式选取至多 4 条近期、当前有权访问且内容不超过 1200 字符的记忆，此外保留已有相关记忆检索。超长记忆不进入这次近期选择；不暗中截断来源。完整工具回执可能超过模型输入限制，此时按既有适配器拒绝并暂停，不自动摘要或删证据。

调度只在现有授权 Runtime 的 process_one 中运行。它不会安装常驻任务或启动进程；非终态、未暂停活动（包括等待用户或审批）会阻止新的探索活动。

## 7 管理入口

```sh
python3 -m digital_life --data <隔离实例目录> exploration status
python3 -m digital_life --data <隔离实例目录> exploration enable --max-activities 12 --max-rounds 3 --interval-seconds 300
python3 -m digital_life --data <隔离实例目录> exploration disable
```

这些命令只读取／保存配置，不解除锁、不部署、不运行模型。实际探索仍需要独立授权运行该隔离实例和相应工具。现有 authorization 模式仍需审批；enable 不等于授权自动读取。管理面板本轮未新增探索控件。

旧可执行版本不理解新增事件语义和 V2 请求。不要把 schema 版本不变解释为任意旧版本可安全接管探索；回退前应停用探索、停止并核对未完成工作。当前没有声明已完成旧二进制的探索状态回退验收。
