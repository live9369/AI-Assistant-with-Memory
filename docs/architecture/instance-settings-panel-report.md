# 实例配置面板实现与验收

日期：2026-11-17（Asia/Shanghai）。对应[设计](instance-settings-panel-design.md)与[使用说明](../operations/instance-settings.md)。

## 结果

新增root专用“实例配置”，21个分组覆盖身份与交流、人格、价值、预算、近期上下文与召回、来源权重、各学习及认知模块、行为系数、探索、维护、目录权限和恢复设置。模型与授权、账户、记忆域继续使用原页面并提供入口。

参数使用带范围的表单、布尔开关和高级系数分组；窄屏使用分组下拉框。按组保存，要求原因、人工确认和修改前后确认；版本不匹配、未知字段、非法数值、非root、运行中修改均拒绝。不会通过设置页关闭来源、权限或停止保护，也不提供启动/部署/唤醒按钮。

预算与上下文相关参数已经接到实际运行逻辑。新活动创建时保存设置快照；旧活动沿用原参数，不补额度。独立模型调用模式保持不变。人工人格/价值调整经原有服务追加版本，配置依据与确认明确标记为控制记录，不冒充独立实证样本。模块开关复用原configure，不自行改开关表。

恢复设置复用既有原子文件替换和控制库记录，另有设置日志；不宣称跨运行库、控制库与文件的分布式原子事务。当前原生设置页不为受保护schema4提供旁路。

## 针对性验证

- 新增9项临时实例测试全部通过：21组保存、实际模块读取、root访问、运行中拒绝、版本冲突、非法配置回滚、身份连续、新旧预算与上下文/来源权重接入。
- 原有管理、账户、聊天表达、开发步骤共51项相关检查通过；未运行全量套件。
- Node语法检查通过；真实浏览器完成临时实例登录、按组切换、修改确认、保存并重新读取。
- 375px核对无页面横向溢出；1280px核对桌面布局，修复既有通用表单规则造成的外层双列冲突。最终表单与fieldset同宽720px，保存操作位于字段之后。
- 页面证据：outputs/instance-settings/configuration-page.jpg。测试使用临时数据，无真实模型调用。

首次账户测试夹具在创建第二账户后才尝试初始化root密码，被既有规则拒绝，调整为先初始化后创建普通账户；重跑通过。首次相关检查有不存在的测试模块名及受本机端口权限影响的HTTP用例，修正选择并获得本机端口权限后51项全部通过，不将其计为产品通过。保留实际检查范围，不以次数冒充全项目验证。
